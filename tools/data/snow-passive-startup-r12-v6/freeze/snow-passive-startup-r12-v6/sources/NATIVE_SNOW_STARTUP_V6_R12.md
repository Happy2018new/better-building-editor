# Native Snow Startup V6

V6 retains V5's exact e757ef5 Windows launcher, planned protected MCP client,
PMv2 physical capture guard, native-alpha marker, config, binaries and fixed
90/110/150 deadlines. It is a single background startup prerequisite; no snow
fixture, texture switch, input, production acceptance or automatic retry.

The V5 review found concrete deadline and restoration edges. V6 checks the
parent observation deadline again after the final capacity query and refuses
to launch once exhausted. Cleanup discovery receives the parent's remaining
budget rather than a fixed three seconds. Owned termination rechecks creation
identity on the exact opened handle and clamps the actual native wait to the
remaining deadline. Launcher reaping uses only the time left after that wait.
No shared `_session.py` or native binary changes are required.

Marker installation is journaled before copy. If copying raises after writing
partial bytes, the observed owned target hash is retained and original bytes
or original absence are restored only while the target still matches that
snapshot. External drift or an unobservable partial target remains a cleanup
failure; it is never silently accepted or overwritten.

The first scheduled sample target and first post-ready sample target are
locked in the supervisor receipt before capture. The latter is the first
attempt whose owned manifest snapshot has `state=ready` and `ready=true`.
Both original attempts are reported. The selected post-ready attempt must
still pass the observer's before/after readiness, physical dimensions,
identity, compositor freshness and nonblank checks; early failure, missing
after-state or a skipped attempt fails that result. Later successful samples
cannot replace it. Launcher exit zero and a visible world in the selected PNG
are also required to call the startup prerequisite healthy.

All known child waits are finite and cleanup is reserved from T0+110 through
T0+150. WinAPI inspection, Python filesystem operations and final receipt I/O
remain synchronous; this is not an independent OS-level watchdog. Any measured
parent deadline exceedance fails the run. No speculative I/O redesign is part
of this correction.

The existing V5 document's deferred h0 four-state native control remains a
proposal. If startup becomes healthy, prepare a concrete built-in
`test.layers.snow` poppy subfixture at the declared cell and public camera,
with original/own-alpha cold-load controls and fixed comparison pixels.
Preserve the built-in source position and native movement semantics; do not
normalize offsets or move cells to improve results. All prospective fixture,
support and camera-qualification cells must lie inside the actual 1.21 world
height interval `[-64,320)`. Startup-only imposes no legacy player-foot bound;
a valid starting Y of -60 is not grounds for rejection.
