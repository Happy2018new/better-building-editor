# 透明建筑投影与星点

> **实验分支，未通过最终实机验收，不应合并为修复。** 天空、草叶、UI、占用过滤回归通过，但普通世界海岸场景中，后绘制的真实岛屿和水面覆盖了前方投影的石英墙。下面记录的是失败候选的设计与验证边界。稳定版本仍保留原投影深度写入。

## 最终否决原因

2026-10-06，网易 3.9.0.401155 / 游戏显示 v1.21.120，普通世界、美丽的天空开启、gfx_msaa=2。完整示例建筑在原点 `(0,64,0)`、alpha `.45` 下，石英面在天空背景处仍存在，在远处岛屿和水面背景处被覆盖；玻璃等部分仍可见。证据为本地 `.runtime/compositing_final_scene/{golden,starry}.png` 和 `.runtime/particle_background/user_scene_now.png`。

保护层的远深度只能挡住天空。后绘制且比这个远深度更近的地形依然通过测试，覆盖之前的投影颜色。把保护层改回投影的真实深度，又会挡住后期星点。只调整同一份深度／二值模板无法同时保存投影深度和被其遮挡的真实墙深度。

GPU 工具的真实墙夹具先画墙，再画投影，因此 52 项断言通过只证明这个给定顺序下的数学性质，不能证明游戏实际提交顺序。隔离实机探针检查了天空中投影的表面，以及“投影→墙→星点”时星点被挡，却遗漏了同一夹墙场景中投影颜色是否仍存在。完整世界背景验收发现并否决了这个缺口。

下一方案必须先通过以下验收，再推广到完整建筑：背景天空／远岛／水面均不能覆盖前景投影；`相机→投影→星点→墙` 应见星点，而 `相机→投影→墙→星点` 应被墙挡；UI 镂空、投影的连续透明度和动态占用过滤也须保留。

资料库及当前运行时的 ActorRender 方法列表没有确认到 BlockGeometry 的队列／离屏目标控制。后处理虽能读取最终场景深度，却不能找回此前被投影深度挡掉的场景信息。原生粒子可绑定 `atlas.terrain`，但把完整动态建筑改为粒子几何会失去现有 native 方块网格生成能力，不能当作等价小修。恢复早期星核深度写入的折中也无法保证夹在投影和星点之间的真实墙遮挡正确。

问题来自原生绘制顺序：透明 BlockGeometry 在 native 星点之前写入深度，后面的星点因此被半透明建筑当作实墙挡住。直接关闭投影深度写入又会让后绘制的天空抹掉建筑。

## 合成方式

一个投影使用两个客户端实体，共享同一份已合并的 native geometry；不会为了保护层重新合并建筑。

| 绘制部分 | 颜色输出 | 深度行为 |
| --- | --- | --- |
| 透明建筑，uniform4.x=19487 | 原有连续 alpha 混合 | 测试深度，不写深度 |
| 天空保护层，uniform4.x=19488 | RGBA 全零，源 alpha 混合不改颜色 | 仅写极远深度，保留更近的真实地形 |
| skyplane / cubemap / end_sky | 原有天空颜色 | 顶点 z=w，LessEqual |
| 原生星点 | 原有三类配色及加法混合 | 保持深度测试，不写深度 |

保护层的 clip z/w 为 `1 - 1/32768`，转换为窗口深度后与天空 1 之间至少有一个 D16 深度级。原 clip z/w 通过已有 varying 传到 fragment，用于剔除原来就在近／远裁剪范围之外的部分，避免镜头穿进建筑时残留天空遮罩。

纹理 alpha test 先于保护层的零颜色输出，草叶的透明洞不会遮挡天空。移除三类 BlockGeometry cutout 基材质的 `EnableAlphaToCoverage`，防止 MSAA 将零 alpha 保护层的所有深度样本取消。这些材质也用于 UI 预览，影响的是 cutout 边缘采样；alpha test 与正常 UI 深度测试仍保留。

所有覆盖的 terrain 材质显式声明 `msaaSupport: "Both"`。在当前网易 3.9 客户端中，仅依靠原生父材质继承这个值，冷启动第一次绘制树叶会弹出 `Late creating a PSO for material: netease_block_as_mesh_blend_alphatest` 断言；显式声明后冷启动实测通过。原版也有父子材质都显式声明 Both 的配置。此处没有猜造报错中未公开格式的 `renderTargetsFormat` 字段。

三个 cutout 基材质的覆盖也显式保留原生父链、宏、单双面和深度偏移定义。仅写无父类的 `-states` 覆盖，在本机导致 UI 草叶全部消失而世界透明子材质正常；补全原生继承定义后，两处冷启动均能显示。不能用宿主脚本模拟 JSON 合并的结果代替引擎实测。

## 生命周期

`projection_backdrop.py` 管理共享几何的附加、显隐、群系参数、跟随和销毁。bridge 与大投影入口同时创建两实体，等待 renderer 就绪后挂载，再替换旧投影。失败时保留旧投影。

占用过滤复用原有双缓冲 geometry 名称。主模型继续使用 uniform 选择缓冲，保护层使用 native visibility 选择同一缓冲。提交失败恢复实际可见性快照，避免透明度已改但主模型提交失败时留下错误的天空遮罩。全部变空、重新出现、停止及迟到回调均清理或同步两实体。

## 可重复验证

```powershell
python -X utf8 -m unittest discover -s tests
python -X utf8 tools/verify_projection_depth.py --headers '<游戏目录>/data/shaders/glsl' --browser '<Chromium 路径>' --report '<报告.json>'
```

GPU 工具编译正式 shader、解析安装游戏的 native 材质和仓库覆盖，用 D16/D24、单采样/实际 4× MSAA 验证前后星点、实墙遮挡、投影表面、cutout 镂空、近远裁剪。移除保护层以及强制开启 A2C 是负对照。工具使用 SwiftShader 的真实着色器执行，但不代表已捕获 Minecraft 自身的 draw calls；引擎的实际顺序须另外冷启动游戏验证。

实机验收使用开启美丽的天空的普通世界，检查斜视、地平线、仰视正上方、树叶和草、真实墙体，以及 UI 网格和占用过滤。材质或 shader 修改后冷启动，避免热更新结果与最终发布状态不同。

## 效果边界

太阳、月亮及原版 stars 不改材质。太阳背景的高亮按用户确认保留。云也未改变。

这个实现没有重排引擎队列，也没有实现顺序无关透明。晚绘制的加法星点不会根据透明建筑的层数或 alpha 自动衰减；建筑多层透明面、自交和水冰之间的混合仍依赖引擎提交顺序。保护层是二值天空遮罩，并不重建完整的天空透射。
