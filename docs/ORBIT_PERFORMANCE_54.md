# 椭球旋转卡顿：阶段 54

在网易 3.9.0.401155 开发客户端、1920×1080、RTX 4060 Laptop 的同一个 64×128×64 椭球上比较。文档有 20,649 个方块，104 个非空 16³ 分块。网格和动画开启。旋转使用真实按住鼠标的输入，F11 模式读回 `IsTouchWithMouse`；每条路径持续 6 秒、两个往返周期，额外记录松手后 0.7 秒。角度中心为 35°/0°，小幅 ±6°，大幅 ±45°。

记录的是 `GameRenderTickEvent` 进入 Pyreact 回调的间隔，包含上一帧 Python 工作造成的停顿；另外记录 Python 回调 wall time 和 SDK `GetFps`。它不是 GPU PresentMon 捕获，也不是手机硬件结果。采样期间没有新增原生模型构建。未有效拖动或失去前台的样本不计入结果。

## 根因与修复

有符号分块顺序在视线跨过轴向时改变。慢帧 cProfile 显示 105 次 `BaseUIControl.SetLayer` 累计约 179–184 ms，其中约 178–183 ms 是 `_gui.handle_input_mode_change`。即使 `syncRefresh=False, forceUpdate=False`，SDK 的 `gui.set_layer` 仍会调用该输入路由重建函数；仅减少最后的强制刷新无效。文件名显示为 `minecraft/gui.py`，实际 Python 导入名为 `gui`。

`native_layers.apply_layers` 在同步的一批公开 SetLayer 调用内临时合并相同参数的输入路由通知，随后恢复 SDK 原函数、重放一次，并保留整批的最后一次层级刷新。异常退出也恢复并重放。找不到此 SDK helper 的版本继续走公开 API。只用于本模组场景分块和方向控件；不永久替换引擎回调。触屏按住时仍沿用原来的延后层级更新规则，以保留滑动/松手事件。

PC 正面小幅路径的 Python 最大回调耗时从 194.00 ms 降到 11.84 ms，大幅路径从 205.73 ms 降到 11.55 ms。这支持“消除了重复输入路由计算造成的长停顿”，不保证任意设备、任意建筑都没有慢帧。修复前 F11 的记录缺少松手后的间隔，故没有放入同口径的前后表。

原始记录位于 `.runtime/stage54_orbit_pc_before.json`、`stage54_orbit_pc_profile.json`、`stage54_orbit_pc_after.json`、`stage54_orbit_touch_after.json` 和 `stage54_orbit_touch_inside.json`。复测入口为 `tools/profile_orbit_angles.py`，可加 `--pc`、`--depth 40 --zoom 3`；`--profile` 只用于慢帧定位，不能与无 profiler 的帧间隔直接比较。

额外通过内部金块选取、擦除和撤销的后台回调检查，并查看金块与椭球内部的实际窗口截图。用户随后要求只做后台检查，后续完整真实触屏交互套件未完成；上述 F11 旋转记录是在此前有效前台输入下完成的。后台检查不替代手机触控硬件测试。
