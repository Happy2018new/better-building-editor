# 大范围建筑实现与验证

2026-09-20。当前按用户要求限制 X/Z ≤ 64、Y ≤ 100，最大 409,600 个位置。大范围沿用原有工具和撤销接口。下方 256×384×256 的记录属于历史版本，不代表当前上限。

## 数据与任务

- `BlockStore` 按 16³ 分块：空气省略，均匀分块只存材质索引，混合分块使用 4096 个 uint16。最大尺寸共 112 个分块，全部混合的原始体素数组最多约 0.875 MiB（含顶部不满块的预留空间），不含 Python 对象、调色板、历史、原生模型与引擎本身的内存。
- `Selection` 使用每块 4096 位的位图，整区全选不创建 409,600 个坐标元组。材质总数、非空气数量、图层计数随编辑维护，界面查询不扫描整区。
- `EditJob` 在副本上处理，原数组按写入复制。每步目标 6 ms；复杂工具以 128 格或一列为最小工作单元，个别工作单元可能超出目标预算。成功后发布一次；取消或越界失败保留原草稿。锁定层与工具参数取任务开始时的快照。
- 撤销记录最多 50 步、估算 64 MiB 预算，至少保留最近一步；估算不是进程 RSS 上限。全区随机纹理、连通填充等依然可能耗时较长。

## 预览与投影

- 所有草稿保留一对双缓冲原生预览。总览使用原始尺寸与表面方块，剔除被已知不透明完整方块完全包围的内部方块，保留孔洞、薄墙、远端细节和材质附加值。未知/透明/非立方方块不会遮蔽相邻方块，不进行体素降采样。
- Python 表面提取按空间分块缓存，只重新提取单格编辑及相邻面涉及的分块；最终合并为一个原生模型，使墙体与玻璃使用同一次原生绘制的深度关系。不同 PaperDoll 即使原点相同，也不能保证透明面跨控件正确遮挡，因此不再每块独立创建渲染控件。原生提交间隔至少 80 ms，上传中的缓冲不覆写；原生合并并不是局部网格更新。
- 底部网格逐格绘制：64×64 对应 65+65 条边界线，没有网格步长采样。观察前移/后移只改变平滑相机缩放，不裁掉体素，不提取或提交几何。四向平移时扩大原生控件边界并保持其中心，避免放大模型仍可见却被离开视口的控件提前剔除。
- 正交 UI 顶点着色器按每次绘制的矩阵和最大坐标范围线性归一化深度，避免高倍率下表面被固定近远裁剪面截断；XY 投影、面之间的深度次序及世界透视分支保持原样。最大实心结构在 8.72、19.2763、100、1000 倍及不同斜视角下的实际表面像素和逐格拾取已检查，不把有限倍率测试当作浮点精度无限的保证。
- 鼠标滚轮缩放保持指针下的世界射线不漂移。“定位选中”以点击格为中心调整到每格 20 设计像素，便于从大结构总览转入精确编辑，仍保留完整模型。相机定位、平移和缩放仅改变姿态，不触发几何重建。
- 总览支持直接编辑。“精细”按钮或精细视图中心可进入最大 32³ 的真实方块区域。射线命中和轮廓使用文档坐标，支持远端与地下编辑；选取单格不会不断重置预览中心。
- 图层列表每页 16 行。完整、切面、单层共用三维视口和可编辑 Y 高度，不再使用独立的二维分页画布。
- 大范围世界投影保留附近最多 32 个 16³ 精确分块，离开后撤掉演员实体，靠近再加载。生成时冻结建筑与显示条件，更新按钮重新取快照。
- 单次预览的额外保护阈值仍为 750,000 个表面方块，当前文档上限 409,600 已小于该值。最大实心长方体保留所有 409,600 格数据，仅需 32,888 个外表面方块。全空气/不支持模型的提示不表示草稿丢失。
- 原生 `CombineBlockPaletteToGeometry` 调用本身不可分帧；表面提取按时间预算分帧，最终 SDK 合并仍可能短暂停顿。当前 SDK 未找到模型释放接口，长时间不断创建不同几何体仍可能积累引擎缓存；不宣称任意材质、任意连续编辑时长都有固定内存或帧率保证。

## 存储与网络

- v1 小配置继续兼容；v2 是调色板加压缩分块格式，每个混合块校验解压长度、校验和、材质索引和边界。重复块和不完整数据拒绝发布。
- 本地大配置以 v3 小索引与独立分页保存。每页最多 8 个传输包，分页在计时器中逐步写入；索引最后提交。删除后逐页清空数据，编号单调递增，避免延迟清理覆盖新配置。SDK 没有删除配置接口，清理后保留小的空配置文件。
- 上传使用递增序号和逐包确认，冻结数据后发送。每包最多 64 个均匀块、4 个混合块，并受约 16 KB 数据预算限制；包头和 JSON 字段开销另计。捕获也按包返回，客户端仅在接收完整文档后替换草稿。
- 服务端使用引擎身份，限制一个玩家一个任务，上传空闲 60 秒超时。读取或写入遇到未加载方块时通过 `DoTaskOnChunkAsync` 等待区块。
- 世界操作保留完整预检、冲突检查、保护检查、分批写入和失败回滚。日志每 1024 条压缩，避免数千万 Python 元组常驻。日志当前仍在内存，不能提供游戏崩溃或进程终止后的持久恢复保证。

## 历史：256×384×256 完整模型验证（2026-09-19）

- 阶段 26 最终新进程复测：最大实心模型首次构建约 23.31 秒，完整尺寸、最远列、横跨整区的细线、总览单格擦除/撤销及 32³ 精细视图坐标共 8 项通过。三张关键截图已打开核对，四种比例的布局/拾取 60 项通过。以下其余耗时与采样为此前完整模型版本的记录，不作为本轮前后对照。
- 旧总览把每个 16³ 分块缩成一个方块，256 格宽度因而看起来只有 16 格。这是预览实现的降采样，不是已证实的 SDK 16 格上限。当前使用原尺寸调色板与真实方块索引；全实心最大文档保留 25,165,824 格数据，预览使用 520,712 个表面方块。
- 新启动的真实游戏实例，1920×1080 客户区，最大实心模型首次生成实测 19.82 秒（含脚本查询与等待）。已实际打开静止镜头截图 `solid_stationary_final.png`，核对完整外形与框线；再打开 `solid_rotated_final.png` 核对旋转、缩放后的显示。SDK 返回模型名称本身不视为渲染成功的证据。
- 原生 PaperDoll 会在首次模型初始化时重设绘制深度，单纯声明 zIndex 不能确保大型模型显示。双缓冲晋升后重新提交一次姿态，并在 0.2 秒后刷新原生层级，确保镜头不动时也能显示；没有增加静止状态下的连续模型提交。
- 当前版本真实鼠标拖动 6 秒、14 次滚轮事件，10 秒 Tracy 采样得到 561 帧，即 **56.1 FPS**，`cap-20260919-101401-7aeb39`。采样前确认完整模型已显示，期间无外部剪贴板查询，动画开启，报告 `profile_exact_solid_release.json` 标记 workload.complete=true。这是当前开发机单场景结果，不是所有材质、硬件或编辑步骤的帧率保证，也不与旧降采样结果作等价比较。
- 81 项宿主单元测试通过，涵盖分块边界、孔洞、玻璃、隐藏图层、裁剪、附加值、统一选区与网格几何。9 项游戏内选区检查、19 项三维交互检查、8 项完整大模型检查通过。远端 `(255,383,255)` 与中间细线 `(128,0,48)` 可直接命中，总览擦除只修改一格，撤销恢复；32³ 精细视图的原点 `(224,352,224)` 与总览坐标一致。
- 一次隔夜保留的旧进程在约 10 FPS 状态下生成超时；重新启动后的结果如上。测试辅助进程改为隐藏启动，避免采样程序的新控制台抢走鼠标焦点；未完成工作负载的采样不计入最终性能结果。
- 最终四种比例共 60 项布局、拾取、原生裁剪与专注视图回归通过；窄窗口工具栏不会溢出。完整工作流 16 项通过，包括建筑库保存 / 载入 / 删除测试配置与投影启停，测试后恢复完整动画。
