# 2026-10-17：用户提供的 3.10 方块表与现用 3.9 表比较

## 结论

**这两份 dump 的原版方块数据完全一致。** `minecraft:` 均为 **1,321 个名称、15,839 条名称＋aux 记录**，没有新增／删除名称、状态组合、状态键、状态类型、默认 aux 或 aux 重映射。按名称＋aux 排序并规范 JSON 后，原版记录的全部字段 SHA-256 一致；`block_id`、`name_hash`、`network_id` 也没有变化。

整份文件新增的 **709 个名称／709 条记录全部属于 `modern_projection:` 项目内部方块**。它们说明本次 dump 中注册了更多预览／渲染代理，不构成 709 种新增原版方块的适配任务。新代理均为 aux=0、空状态集。此前已有的 19 个项目代理只改变了 `block_id`，名称、aux、状态、`name_hash` 和 `network_id` 未改变。

本次还直接解码现用 `block_registry_data.py`，逐条核对全部 **1,340 个名称／15,858 条 typed state 记录**，与归档旧表一致，默认 aux 差异为 0。因此，本次比较没有发现生产表漏掉的新原版名称或状态，也没有发现需要由旧 aux 迁移到新 aux 的记录。

## 适配工作涉及哪些

1. **原版名称、状态、aux、默认值和旋转／镜像输入集合：本次差异引入的新增适配量为 0。** 现有输入集合保持一致，无需为这份新表编写旧 aux 到新 aux 的迁移，也无需因“版本号变了”重新穷举全部普通方块。已有变换正确性与产品行为仍按原关闭条件维护。
2. **项目内部代理的注册与目录边界：若后续正式切换全表，需要先处理。** 当前 `block_registry.catalogue_values()` 只排除 `modern_projection:preview_` 前缀；将新表直接送入现有生成器会把 27 个 `centered_*` 代理也带入默认目录。应明确它们是内部渲染代理，并检查其他目录／统计入口，避免扩张用户可选方块列表。这是未来重生成的具体风险，本次未改生成器或生产目录。
3. **代理的底层编号：使用名称与语义状态重新解析。** 19 个旧代理的 `block_id` 已变化；依赖固定数字编号的外部脚本／捕获数据需要复核。现用生成表保存名称、aux 与 typed states，没有把这些 `block_id` 写入注册表，不需要据此迁移建筑中的名称＋aux。
4. **版本与证据来源：保存兼容核对记录，正式迁移另作完整版本包。** 当前表的来源仍真实标记为 3.9，不能只把 `SOURCE_VERSION` 或 SHA 改成 3.10。全文件 SHA 会随项目代理注册变化；traits、NBT 默认、邻域／轨道、含雪、液体等派生表存在来源校验。后续若正式更新源表，需要为依赖建立可追溯的重新生成／复用依据，并核对版本包。原版语义相同允许缩小调查范围，不能自动更改旧实机证据的版本或哈希。
5. **编辑器与投影的行为适配：继续处理已确认的显示问题。** 方块表没有模型、材质、邻域几何规则、动态帧或 block entity NBT 内容，无法据此关闭植物缺画、铁轨连接、压力板厚度、水／含雪、书本、物品框内容、旗帜／盾牌等专项。应优先对人工检查已缩小的问题做最小诊断和代表回归。

建议当前保留现用生产表，以本报告建立“本次提供的 3.10 原版 palette 与现用表一致”的证据，直接继续已有缺陷定位。由表差异引入的新增原版适配工作为零；现有渲染和 NBT 工作的剩余工时需依据实际诊断更新，本次不另加一轮“全量 3.10 新方块适配”预算。
