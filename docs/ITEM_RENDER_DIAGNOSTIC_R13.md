# R13 物品附着渲染诊断

本轮结果用于定位物品展示框／展示架内容及附魔光效的可行原生渲染路径。
编辑器与投影的正式功能、场景深度遮挡及附魔光效目前均未验收。

## 已完成的有限实验

1. 客户端临时 `modern_projection:anchor` 的 `SetModel` 返回 `-1`，在绑定物品和截图前停止；恢复通过。
2. 私有不透明骨骼与已有 `ceshi_body` 都能 `CreateFreeModel`，等待该客户端 actor 的 root 初始化后，`SetModel` 仍返回 `-1`。这只排除该具体路径，不能推导所有客户端实体均不可用。
3. 服务端创建唯一临时 NPC anchor，复制到客户端后，私有骨骼 `SetModel` 成功；同一实体同时用于 `RenderEntity` 和 `BindItemToSkeletonModel(..., False)`。10 张原始 WGC 截图中，首尾不透明本体均为 121 像素，普通钻石剑产生 1,375 个稳定差异像素，移除物品后的差异为 0。画面中的剑接近侧向，显示朝向仍未验收。

第三项运行耗时 64.983 秒，文档、相机、页面和临时 actor 恢复通过，错误为空。
服务端证据是 `DestroyEntity=True`，随后客户端类型查询实际为 `None`；旧实验没有再次查询服务端 actor 类型，因此不能写成服务端和客户端都已直接验证不存在。

## 证据与边界

- `docs/evidence/item-skeleton-r13-v1/archive-index.json` 登记失败路径与资源解析实验的原始字节；无截图，因为在截图前按守卫停止。
- `docs/evidence/item-server-skeleton-r13-v1/archive-index.json` 登记冻结候选、源代码、owner 合同、原始运行报告、10 张截图与捕获回执。
- 服务端临时 actor 只属于诊断，未建立任何面向普通客户端的任意生成实体请求。未更改玩家、库存或已有实体。
- 旧 server owner 合同继承了“无 world mutation”总字段，但此次明确创建了诊断实体；该字段是记录错误，不可据此宣称没有世界实体变化。后续独立冻结实验改为明确登记一枚临时服务端实体，并查询服务端类型确认消失。
- 所有实机操作均复用唯一已登记实例，后台 WGC 捕获，无窗口激活、缩放或桌面输入。

## 下一阶段

先独立冻结普通物品两个姿态及较大的 UI 比例，按稳定像素、包围盒比例和恢复证据选择可见面姿态。随后另行冻结同姿态普通／附魔对照，要求附魔差异位于普通物品区域内、普通对照稳定、附魔画面有时间变化。任何 API 成功回执都不替代像素验收。

正式集成仍需要独立的 actor／模型／物品生命周期模块，以及编辑器、投影的相机和裁剪模块。若最终采用服务端 actor，权限应限制为已有渲染 owner 的固定类型、固定上限与自身 actor 清理，不开放任意实体类型、坐标或库存接口。
