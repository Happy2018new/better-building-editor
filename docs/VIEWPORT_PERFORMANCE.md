## 放置连续性与大视图

`verify_preview_frames.py` 将游戏确认为前台后，仅截取三维区域；用真实鼠标连续放置四格，按图像中的模型像素覆盖检测建筑消失，并保存最少覆盖帧及相邻帧供视觉核查。

- 去掉重复提交后的单预览版本：154 个采样画面中有 9 个模型消失样本，最低模型像素数为 4。
- 最终双缓冲版本：约 3 秒采样 92 个画面，0 个消失样本；初始模型像素 6113，最低 6111。四次点击均实际执行，最终命中坐标升至 Y14。
- 前后世界光照会变化，所以覆盖阈值使用每次采样自身基线；不会把两次像素绝对数量当作画质指标。这种采样验证不等于覆盖游戏的每个输出帧，也不保证任意大建筑和慢速设备的 GPU 就绪时间。
- 1920×1080 的专注视图面积为普通视图的 2.3073 倍，原生 Scene/指针/两个预览控件在展开和还原过程中保持相同 ID。20:9、4:3、16:10、16:9 下的场景、属性面板边界及三维拾取共 44 项检查通过。

## 历史：2026-09-19 分块预览与快速输入

本节记录的是阶段 24–26 的多原生控件实现；阶段 27 保留 CPU 分块缓存，改用一对完整原生模型，以修复玻璃与墙体遮挡。下文局部原生提交次数不代表阶段 27。

当前实现将双缓冲下沉到空间分块。普通文档分块边长为 8，根据体积增加边长，以不超过 128 对原生控件、每组缓冲的调色板声明格数总计不超过 32 Mi 为限；两组缓冲的声明格数预算合计为 64 Mi，这不是原生内存字节数的保证。最大文档因此使用一对完整模型。每个模型调色板保留整场景尺寸，隐藏面判断跨越分块边界。普通建筑局部编辑只提交受影响的分块；最大文档仍需重建完整表面。预览生成按约 3 ms 的 Python 时间片推进；这不包括原生网格提交和 GPU 上传耗时。

空块的控件在加载文档时分配，实际有方块时才提交模型，避免跨边界时新增 UI 节点。一次修改只标记所在块及六个相邻格涉及的块。相同表面内容直接复用，上传中的缓冲不会被覆写。统计和历史面板在停止点击 0.4 秒后合并发布，每次放置仍各自保留撤销事务。

真实输入检查还定位到两个漏点击原因：局部按钮 down 在模型上传时可能丢失，以及全局回调旧有的 20 ms 去重会吞掉停顿后连续到达的独立点击。现在用页面全局 down 兜底（排除导航控件）并按按下/释放配对去重。

- `tools/verify_rapid_placement.py .1`：最终复测 40/40 真实鼠标点击，约 4.17 秒，跨 5 个分块边界，只提交 8 次局部模型；最后一次放置独立撤销通过。此前一次记录为 4.31 秒、11 次提交，合并次数随帧调度变化。
- `tools/verify_preview_frames.py rapid_latch`：3 秒 / 121 个采样画面，4/4 次真实放置，0 个模型全空样本，最低原屋顶覆盖率约 95.54%。该测试不是逐帧 GPU 捕获，不能推及所有设备。
- 触控放置 10 项、指针释放 28 项回归通过；触控是 Windows 引擎中的触控回调模拟，不等于手机真机验证。

以上是功能连续性和本机采样证据，不把单次记录当成所有场景的帧率保证。大范围第一次建模和大批量编辑仍需等待原生几何上传。
