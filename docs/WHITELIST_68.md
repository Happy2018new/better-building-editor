# behavior_pack 模块白名单复核（阶段 68）

2026-09-23。范围仅为 `behavior_pack` 下全部 `.py`，包括业务代码、Pyreact 框架及示例；宿主 `tools`、`tests` 和调试器不作为发布行为包审查。

后续更正：本阶段的每帧 4 次模型层级队列会将新姿态与旧层级混用，导致旋转时分块闪烁。原有“无几何重建”的检查未覆盖连续画面的遮挡正确性。该队列已在[阶段 69](ORBIT_REGRESSION_69.md)删除，改为固定层级及着色器共享深度；下文是历史记录，不应恢复此队列。白名单改动继续保留。

## 官方依据与修改

依据[网易 Python 模块白名单](https://mc.163.com/dev/mcmanual/mc-dev/mcguide/36-%E5%AE%A1%E6%A0%B8%E4%B8%8E%E4%B8%8B%E6%9E%B6/%E8%AF%BE%E7%A8%8B07-Python%E6%A8%A1%E5%9D%97%E7%99%BD%E5%90%8D%E5%8D%95.html)。正文说明限制从 2.9 开始，不包括开发者自定义模块和接口。此次读取并规范化表格得到 456 个允许模块，快照保存在 `tools/modsdk_module_whitelist.json`，记录来源及检查日期。

原实现共发现 8 处不在白名单中的导入：

| 模块 | 位置 | 修改 |
| --- | --- | --- |
| `gui`，2 处 | `pyreact/native.py`、`projection/native_layers.py` | 删除内部输入路由拦截；通过公开 `SetLayer` 更新。模型排序合并重复目标，每帧最多 4 个控件；触屏按住时延后，松手后继续。卸载控件的请求会丢弃。 |
| `array`，3 处 | `projection/storage.py`、`codec.py`、`journal.py` | 改用白名单 `struct` 和内置 `bytearray` 实现紧凑整数缓冲区。混合分块仍是 4,096 个 16 位材质编号，数据载荷 8,192 字节；写时复制与整平面批量写入保留。 |
| `sys`，3 处 | `projection/bridge.py`、`codec.py`、`typography.py` | 显式小端序列化；用内置类型判定 Python 2 字符串，用 Unicode 实际长度判断窄字符构建。保留 SDK UTF-8 和扩展汉字代理对处理。 |

无动态导入替代、未从内部对象间接取得违规模块。`contextlib` 本身在白名单中，仅因原批处理已删除而移除了无用引用。其余布局缓存、静态文字缓存、字形差分和按钮控件复用仍保留。

全套 268 项离线测试通过。回归覆盖字节格式、整平面切片、写时复制、非法值不得损坏缓冲区、旧版混合分块读取后编码字节一致，以及分帧层级写入上限、目标合并和卸载清理。

独立网易开发客户端 3.9.0.401155，实例 `biome68`，内嵌 Python 2 窄 Unicode。无正式世界方块或建筑库写入；测试后恢复内存草稿及原输入模式。

- `verify_whitelist_runtime.py`：无符号/有符号缓冲区、拒绝越界值、旧版 V2 分块字节、V3 分页存档、乱序分段分享/传输、跨压缩页负坐标日志、中文 SDK 字符串与扩展汉字，共 8 项运行时断言通过。最后增加的缓冲区非法值保护通过保留类身份的热装验证，其他实现由本次新实例启动加载。
- 生物群系：用户已确认恢复；重新使用明确含草、树叶及石英的演示建筑验证。PC/F11 各真实点击沙漠和丛林，检查文档值及实际截图；视口内分别有 2,994 / 2,948 个像素符合黄绿染色变化，稳定中性像素超过 59,000。查看完整截图确认石英颜色保持。没有把“标题变了”当作染色成功。
- 最大尺寸：64×128×64，39,944 格一格厚薄壳；创建、撤销、重做、连续 20 次修改及撤销、镜头平移/缩放/深入通过。镜头操作没有新几何构建；连续修改仅构建受影响的 2 个分块；撤销/重做复用原几何。
- PC/F11 长拖：2 倍缩放、视线深入 32 格，每种模式测两个小角度区间和 ±45° 区间，各持续 6 秒。检查按住期间角度持续改变，几何构建计数不增加。没有出现原生断言窗口。
- 日志存在启动时网易 `neteaseHttp.py` / `ui_request.py` 网络回调异常，未出现本项目 Python 堆栈错误。

旧 `verify_biome_tint.py` 的固定坐标依赖旧演示草稿；直接用于满石英草稿会产生无效像素结论。本轮使用显式演示建筑及实时原生视口范围。旧世界当前位置群系测试还依赖群系映射/滚动位置，本轮未据此修改业务，也未声称覆盖全部世界群系与世界投影像素。

## 性能边界

本次以移除违规依赖为目标，没有宣称所有卡顿消失。移除内部路由合并后，原生控件挂载和公开 `SetLayer` 仍有成本。

数据任务 CPU 计时（不包含模型创建）：

| 64×128×64 操作 | CPU 总计 | 最大 step | 撤销 / 重做 |
| --- | ---: | ---: | ---: |
| 全区填充 524,288 格 | 2.15 ms | 2.15 ms | 0.019 / 0.164 ms |
| 一格厚薄壳 39,944 格 | 75.20 ms | 17.03 ms | 0.014 / 0.018 ms |
| 蒙版填充 472,812 格，3 个锁定层 | 521.06 ms | 12.98 ms | 0.022 / 0.039 ms |
| 选区擦除 472,812 格，3 个锁定层 | 502.56 ms | 12.10 ms | 0.021 / 0.017 ms |

`struct` 缓冲区的逐格读写比原 `array` 成本更高，分块/整平面快路径仍保留；复杂蒙版数据处理比阶段 67 的约 137 ms 增加，仍明显低于早期逐格版约 4–5 秒。不同实例测量有调度差异，不能把倍率当成严格微基准。

本轮最大薄壳预览调度约 7.37 秒；连续 20 次修改的同帧批量测试仍出现约 474 ms Python 提交峰值。渲染回调间隔 p95：PC 三种旋转约 32.7–40.3 ms，F11 约 11.5–14.5 ms；F11 松手后排序也有额外成本。它们不是手机硬件或所有设备的帧率保证。后续性能优化须使用白名单与公开 SDK，不能恢复内部引擎模块拦截。
