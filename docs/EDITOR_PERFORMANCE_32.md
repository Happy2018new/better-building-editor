## 根因与改动

1. 空心长方体原先逐格判断整个体积。现在按选区位集合构造六面薄板，交集保留不规则选区、掩码和锁层。厚度 1 的最大结构只访问 39,944 个表面格，跳过内部 484,344 格。墙、框架、底板共用该快速路径。
2. 原先每次更新进度文字/填色都触发根布局。Tracy 中编辑 CPU 约 0.405 秒，编辑墙钟却约 20 秒；10 秒内 `layout` 约 193,892 次。进度改为固定布局，直接更新原生文字、填色宽度与可见性；编辑阶段可取消，预览阶段显示生成进度。
3. 编辑和预览走有预算的渲染帧队列，不再依赖低频游戏计时器逐步推进。关闭 UI 后有计时器回退；卸载帧泵会移交未执行回调。单帧最多一次实际的 16³ 原生提交，廉价缓存/空块步骤共享约 3ms 的预算。
4. 分块缓存同时比较自身、六邻块、显示上下文和完整材质映射。保留数组使用写时复制，撤销和重做先查源数据快照，再决定是否提取表面。材质映射也进入缓存身份，防止撤销后分支编辑复用相同数字 ID 却显示旧材质。
5. 模型槽位更新使用相机签名和发布序号；空闲不遍历 128 个模型，观察方向不跨象限时复用绘制顺序。页面本身已保留挂载；本轮没有测得页面 FPS 的进一步提升。

## 前后移动与光照

前移/后移现在控制独立的视线推进距离，保持缩放不变。渲染、框线和拾取使用同一近裁剪平面，穿过外墙后可以选取和编辑内侧方块；回退恢复外墙。UI 仍使用原生正交预览，不是透视第一人称相机。缩放继续由滚轮和加减按钮控制。

实测引擎 3.9 的方块 PaperDoll 中，`WORLDVIEW[3][2] = SetLayer(layer) - 500`；未公开的 `render_depth` 参数无效。完整块使用 50–177 层，穿过近裁剪面的块使用 184–296 层传递块中心到平面的有符号距离（1/4 格精度）。顶点/片元着色器完成裁剪，已越过的块隐藏；不重新提取调色板或重建几何。原生界面覆盖层在 360–410 层。推进后重新显示已有块只切换可见性，保留缓存中的原生模型，不重复初始化。该矩阵关系需要在其他引擎版本和移动设备上重新验证。

预览使用固定光照，并给方块顶点颜色设置最低亮度，避免封闭空间全黑。既有亮度控件继续生效；世界透视分支沿用引擎光照。以 8³ 石英外壳和内部金块验证：前移 2 格后能看见并选中金块，擦除及撤销均正确。最大空心结构的内部也已截图检查。

关于 `threading`：ModSDK 的 `CombineBlockPaletteToGeometry` 是同步原生调用，文档没有线程安全承诺；资料中的线程工具也要求游戏 API 返回主线程。Python 2.7 的 GIL 还限制纯 Python CPU 并行。本轮没有把引擎模型 API 放到工作线程，而是消除无效遍历、布局重算和重复提交，再以帧预算执行剩余工作。

## 原生输入压力测试边界

鼠标瞬移后仅等待 35ms、按住 60ms，在最大空心结构上连续切换前后移，仍出现部分原生 down 丢失（一次 20 次注入只有 14 次全局 down，20 次 up）；同脚本在 8³ 外壳中通过。120ms 稳定时间、80ms 按压也有失败。中间发现的导航引用清空与画布穿透已修复，但不能把引擎丢失的原始 down 宣称已修复。尝试限制强制层级刷新、重路由局部导航事件后仍失败；另试约 10ms 的原生层级预算，输入复测仍不稳定且长距离推进明显变慢。这些实验代码已撤回。

保留 `python -X utf8 tools/probe_depth_buttons.py` 作为严格复现工具。它断言 20 次交替点击和 4 次单向点击全部收到；当前最大模型上不能稳定通过，失败不计入通过项目。记录目标深度和当前插值深度，避免把尚未结束的动画误判成距离错误。

最大空心结构的 10 秒短按推进采样 `cap-20260920-150356-f5737a` 为 447 帧（44.7 FPS），但部分注入点击未执行，因此只能作为该压力负载的观测，不能宣称 13 次完整有效移动的性能。`SetLayer` 1346 次累计 self 2264.801ms（单次 1.683ms）。前后移动不增加表面提取或几何构建，原生层级更新仍有实质成本；本轮不承诺最大模型下所有导航和点击都稳定 60 FPS。
