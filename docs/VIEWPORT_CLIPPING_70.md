# 视口裁剪、目录白线与分块接缝

本次处理放大后的线框越界、方块目录的白色横线，以及跨分块的平整屋顶出现微小台阶。

## 原因与修复

### 分块接缝

原生模型裁剪使用整数 UI 边界，而场景容器通常位于小数坐标。例如实测场景原点为 `(116.875, 88.515625)`，裁剪原点为 `(117, 89)`。模型内容需要抵消 `(0.125, 0.484375)` 的偏移，才能保持原有坐标。

旧实现只在裁剪范围变化时，为当时已经存在的模型设置抵消量。`PreviewModels` 分帧创建控件，后创建的分块可能错过这一步；在 4 倍 GUI 缩放下，垂直差异约为 1.94 个屏幕像素。不同分块位置因此不一致，平整屋顶出现额外台阶。

现在每个 `PreviewBuffer` 独立记录并应用裁剪原点补偿，两个缓冲面一起更新；首次创建、后续新增分块、尺寸变化及重新显示时均覆盖。裁剪几何也参与模型姿态更新的缓存键。补偿只在变化时写入，不重建方块几何，不改变固定层级或共享深度。

### 线框裁剪

模型、网格、蓝框和炫彩框共用同一个整数裁剪矩形。投影后的线段坐标转换到该矩形的局部坐标。

新增 `clip_stroke`，裁剪整个旋转线条的宽度，而非只裁剪中心线。原生 `GetRotateRect` 与截图像素在部分 GUI 尺寸下仍有小偏差，因此边界保留一个 UI 单位的光栅余量。只缩短碰到视口边界的线段，不移动内部顶点；炫彩 UV 仍按原始线段的参数插值。

### 方块目录白线

复现时，目录上有一行 `(247, 249, 252)` 的像素，正好是后台三维视口的底色。临时只隐藏模型裁剪容器，白线随即消失，目录分类和物品控件不变。

现在场景不活动时隐藏原生模型容器，与已有网格、蓝框和彩框的显隐策略一致。模型控件与几何仍保留，关闭弹窗后恢复已有模型。

## 验证

- 57 项离线测试通过：选择框、线条裁剪、精确预览、深度、双缓冲、分块缓存及行为包模块白名单。
- 干净启动网易开发客户端 3.9，在 1920×1099（4 倍 GUI）及 1280×960（3 倍 GUI）下检查完整截图。画布按引擎的整数 GUI 倍率换算，不能直接使用截图宽度与逻辑宽度的分数比。
- `tools/verify_viewport_clip.py` 覆盖放大后居中、上下左右平移、展开视图，四组原生裁剪范围相同，裁剪框外侧像素检查通过。
- 同一脚本用真实点击检查 PC 和 F11 的“彩色方块”，分类按钮没有异常横行；关闭目录恢复模型；整段相机及弹窗操作的几何构建计数不增加。
- `tools/verify_viewport_seams.py` 核对初次分帧创建、页面往返、64×128×64 文档中新建远处分块及撤销的原生补偿值。32×8×16 平整模型跨分块的浅角度轮廓不再出现超过一像素的额外台阶。
- `--touch` 复用持续触屏拖动回归，小立方体和 64×128×64 样例均通过按住期间连续往返、暂停、松手检查；最大尺寸样例的几何构建计数保持 28→28。
- `verify_preview_depth.py` 的正反面遮挡、进入内部、页面往返、编辑和撤销像素检查通过。最终客户端错误日志与原生断言窗口检查均为空。

运行时证据保存在本机 `.runtime/clip70_checks.json`、`.runtime/clip70_small_checks.json`、`.runtime/seam70_checks.json` 及对应 PNG。临时草稿和原输入方式在测试结束后恢复；未修改世界方块或建筑库。F11 是开发客户端触屏模拟，不代替 Android/iOS 硬件测试。
