# RenderDragon 原生 HLSL 迁移试验

日期：2026-09-27。目标是启动前选择渲染龙，并把法杖的一部分星空算法改成该后端可执行的着色器。

后续已在 `dev` 增加全部 13 个项目着色器的离线 HLSL/DXIL 转换与验证，见 [全量迁移状态](RENDERDRAGON_MIGRATION.md)。后续转换没有解除本文记录的资源包加载与原生接口限制。

**已验证启动即使用渲染龙；已将星空像素算法移植为 HLSL、编译为 DXIL，并在本机原生材质路径中显示出来。普通模组资源包加载相同二进制的对照没有生效，因此尚未完成可分发、自动切换后端的模组适配。** 动画时钟、顶点变形及最终视觉一致性也尚未完成。

## 环境与启动

- 网易 ModPC：`3.9.0.401155`；画面标注内部版本 `v1.21.120`。
- 调试器：MCDK `v1.6.1`；受管实例独立世界、端口及进程身份。
- 实测后端：`RENDERDRAGON D3D12+ PBR D3D_SM65`。
- 显卡：NVIDIA GeForce RTX 4060 Laptop GPU。本轮未测试手机。
- 原生 `.material.bin` 格式版本 `22`，使用 Lazurite `0.11.0` 读写。

本次检查的 MCDK 配置与启动代码没有渲染引擎参数，不能凭空添加 `--renderer`。`deferred_technical_preview` 是世界实验，不等同于选择渲染后端。本机可通过以下原生选项选择引擎：

```text
%APPDATA%\MinecraftPE_Netease\minecraftpe\options.txt
gfx_renderengine:0
gfx_renderengine:1
```

`0` 为 OpenGL，`1` 为 RenderDragon。上面两个值仅用于说明，实际文件应只保留一条该选项。每轮均在游戏进程关闭时备份并写入 `1`，然后启动专用实例；运行期间保持 `1`，以画面中的后端标识确认选择成功。退出后仅恢复该选项，保留其他设置。该文件由客户端共享，不因调试世界隔离而独立。

## 实机结果

| 对照 | 实施方式 | 观察结果 |
| --- | --- | --- |
| 启动即渲染龙，仍使用原始 GLSL | 启动前选项设为 `1`，直接装备测绘法杖 | 原框架可见；自定义法杖/环绕晶体报 `cannot be assigned to an entity`。切换后端本身不会翻译旧 GLSL。 |
| 原生 HLSL 洋红色程序 | 临时将法杖 gem 材质继承到原版实体入口；备份后替换客户端 Actor、ActorForwardPBR、ActorPrepass 中的像素字节码 | 法杖和覆盖到的原版实体呈洋红色，证明新 HLSL 确实由当前 RenderDragon 管线执行。 |
| 原生 HLSL 星空程序 | 同一路径装入本项目星空函数的 HLSL 移植；用法杖贴图尺寸/色块选取表面 | 晶体和握柄出现程序化蓝色星云与星点。这里只证明星空像素算法显示，未验证连续时间更新；仍为盒状晶体和诊断坐标。 |
| 相同可执行字节码，仅放入模组资源包 | 恢复全部原生文件；把上一行的三个 `.material.bin` 和索引放入 `resource_pack/renderer/materials/`；保持相同的法杖材质继承，再冷启动 | 法杖回到原版淡蓝色贴图，没有自定义星空。调试世界资源包链接直接指向项目 `resource_pack`，其路径中的三个二进制文件均存在。此次普通资源包路径没有应用已知可运行的程序。 |

原生星空实例 ID 为 `895e045e123c4abeadbc9d28e39b1c42`；同字节码资源包对照为 `c69b3c46736946dea096798c15eef579`。二者均是新建的测试世界，测试结束已停止。

环绕晶体没有迁移，截图中的 `modern_projection_aura.fragment` 报错属于这部分，不能声称所有渲染错误已修复。

## 实际迁移的代码

源码保存在 `tools/renderdragon/`，不进入正式 `resource_pack`：

- `starfield.hlsli`：移植现有星点、星云、视角高光、握柄稀疏星点和金色矿物算法。使用 `float2/3/4`、`frac`、`lerp`、`atan2` 等 HLSL 写法，全程保留 32 位浮点；Fresnel 幂函数底数增加 `saturate` 防止负数。
- `staff_probe.hlsl`：对接当前客户端三个实体渲染通道的像素输入、纹理采样和输出。PBR 预通道输出三个目标；当前为简化的全自发光诊断输出，不保留完整原版光照。
- `build_probe.py`：使用开发者自己安装的原生材质作为模板，编译像素程序并回写相同格式。只构建，不安装、不修改客户端文件。
- `README.md`：构建环境、命令和限制。

本次使用可加载客户端配套 `dxcompiler.dll 1.6.2106.3` / `dxil.dll` 的本地 DXC，没有替换游戏 DLL。`Direct3D_SM60` 槽位实际对应 `ps_6_3`，`Direct3D_SM65` 对应 `ps_6_5`；按这两个槽位编译并通过 DXIL 验证。共覆盖 Actor 432、ActorForwardPBR 216、ActorPrepass 144 个变体条目，字节码按平台与常量偏移复用。

构建器保留原生顶点程序、深度通道、完整输入语义顺序、已有常量偏移和采样器槽位。早期精简输入签名的版本曾产生 `Invalid Shader / E_INVALIDARG`；恢复完整签名后，洋红色程序进入原生管线。仅修改 Actor 不足以覆盖当前 PBR 画面，ActorPrepass / ActorForwardPBR 也必须覆盖。

此前“模组中放入洋红色二进制但无变化”的旧实验使用了尚未通过原生执行验证的程序，且缺少当前 PBR 预通道，不能单独据其判断加载能力；本轮相同可执行字节码的对照补上了这一验证。

## 当前未完成的部分

1. **普通资源包的加载/绑定入口。** 本轮仅证明直接替换客户端原生材质可以执行，尚无能让发布组件自动加载相应程序的入口。以上结论限定于当前网易客户端与测试路径，不能推断所有 RenderDragon 版本都不支持自定义着色器。
2. **持续时间输入。** 渲染控制器 `color` / `overlay_color` 向 MatColor / OverlayColor 传时间的诊断没有成功。当前追加 `Time` uniform 元数据并尝试读取 `Time.x`，折回 210 秒，非有限值回退到零。声明变量不等于引擎逐帧写入；虽然算法已显示，还没有可靠证据证明此时钟持续推进。
3. **几何与视角一致性。** 沿用原生顶点程序，没有移植晶体尖端变形或真实模型局部坐标。原先直接使用原生世界坐标和导数时出现黑块；改用 UV 局部坐标、固定法线/视线输入并约束幂函数后消失。这里是组合修正，未把根因单独归结为某一个变量。最终的视角相关星空还需要正确传递顶点数据。
4. **材质完整性。** 原生预通道中的发光、法线、运动向量及 PBR 参数只有诊断实现；非目标实体光照也会改变。贴图尺寸/色块筛选不能作为正式材质隔离方式。
5. **其他效果和平台。** 环绕晶体、紫色法杖/金色光点的独立材质路由以及手机后端未验证，不能声称与现有 OpenGL 版本一致。

因此当前结果是“原生 HLSL 像素阶段原型”，并非可上传的渲染龙适配版本。继续集成之前，应解决当前网易版本普通组件可使用的编译材质注册/绑定入口，再完成时间及顶点通道。直接改客户端目录的实验不能作为最终发布方案。
