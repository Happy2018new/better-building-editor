# R26：已知皮肤断言的忽略按钮修复

2026-10-21 追加窗口先修复宿主自动恢复工具中的按钮编号错误。旧实现把 `WM_COMMAND 7` 标记为 `IDIGNORE`；Win32 的 `IDIGNORE` 为5，7为 `IDNO`。此前水v5的实际对话框枚举及仅为关闭执行的回执，也确认“忽略(&I)”控件编号为5。旧工具即使没有报错，也不能据此认定它点击了忽略或恢复了游戏。

两个入口现在共用 `post_owned_ignore`：只接受已知 `DisabledSkinScreenController::onEntered(void)`、`DisabledSkinScreenController.cpp @ 47` 及 disabled cosmetics 断言原文，核对指定game PID与进程创建身份，再重新枚举该进程的唯一断言。对话框必须可见且为 `#32770`；编号5的按钮必须属于同一进程和父对话框、可见、类为 `Button`，并显示中文或英文的“忽略”。

工具先保存已验证目标回执，再重新核对原文、进程身份、窗口类、可见性、父子关系、控件编号、按钮句柄和文字，最后向该按钮发送 `BM_CLICK`。不激活窗口。watcher仍仅允许每个已分配会话恢复一次；未知断言或重复出现会被记录，不能任意忽略其他错误。上层测试调度据此停止新步骤并普通关闭。

本次宿主定向测试验证正确按钮及回执先后顺序，并对错误PID、父窗、编号7、窗口类、文字、隐藏窗口、多个或消失的断言，以及回执写入期间发生变化的目标执行拒绝检查。运行结果和源码hash另存本轮证据，实际游戏结果追加时单列。

这项修改解决已确认的宿主恢复动作错误，不证明原生皮肤断言的起因已经修复，也不证明水v5超时的业务初始化或函数恢复完成。原失败、旧冻结宿主和水正式资格均保留；新冷实例应绑定新宿主hash，不能把更新后的宿主冒称旧冻结文件。

工具修复已提交为 `39bac5bb`。新增回执写入期间进程创建身份改变的负控后，共9项测试通过，独立代码复核无阻断。精确原ID5关闭回执、初始8项复核与最终9项结果分别保存在[证据索引](../evidence/disabled-skin-recovery-r26-v1/index.json)，避免混用版本。新冷实例若没有触发该断言，只能说明本次未观察到弹窗，不能记为新watcher的实机恢复通过。
