# R29 真实写入：拒绝残缺床向确认范围外补件

已修复一个真实写入边界缺陷：蓝图仅含床脚时，现有 head-first 放置代码会主动在目标范围外写床头；蓝图仅含床头时，原生放置也可能补出范围外床脚。旋转或镜像后的目标范围仍可能只有一格，原实现却报告该格写入成功。最小 CPU 复现中，明确记录到产品自己的 `SetBlockNew` 越界调用并覆盖金块哨兵，不依赖模拟原生床物理行为。

`WorldJob` 现在在既有逐格错误边界中执行 adapter 的可选写前校验，hook 在构造时缓存。`WorldAdapter` 只对最终原生前景含床头／床脚状态的格子调用既有 `paired_position`：先检查伙伴坐标在冻结文档内，再核对另一半的状态。使用实际 native 层序，因此逻辑背景床以及水前景／床背景的组合也受到检查。

不完整或状态不匹配的床格在任何 SDK 写入前失败，后续合法格继续写入；不补造蓝图部件，也不扩大确认范围。完整床的含水层、占用状态与 typed NBT 继续走原有写入流程。最终错误或中途取消提示保留首处失败的世界坐标与原因，内部最多 32 条失败记录保持。

root 复跑通过 58 项定点方法：WorldJob 9 项、床边界 5 项、服务器传输 39 项、投影变换到世界写入 5 项。新边界覆盖 252 个参数场景及一条取消链，包括无变换／六操作、同步空气开关、床头／床脚、背景提升、状态错配以及完整含水／占用／NBT 床。内存中禁用 hook 后，14 项原始反例恰好 14 失败、0 错误，证明测试能够检出原漏洞。真实 Python2 编译通过；按范围结构审查保留既有提示，未新增端侧依赖。

原始复现、禁用 hook 的反向控制及修复回执保留在本地 `.runtime/round-20261026/world-*r29-v1.*`；永久测试随代码提交。此为代码及 CPU 写入合同修复，未取得新源的原生像素、床全部原生行为或用户人工接受资格；其他多格方块范围不由此扩大。
