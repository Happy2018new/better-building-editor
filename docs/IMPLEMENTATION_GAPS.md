**编辑器含雪顺序与原生游戏有明确区别。** Wiki 说明植物上放雪可以含雪，但在已有雪中种植物会替换雪；原生也要求先破坏包围植物的雪，之后才能破坏植物。用户已要求编辑器自动模式支持两种放置顺序，因此保留“雪中放植物仍保留雪”的编辑便利；自动擦除先去雪、再保留并提升植物。严格前景／背景继续只改选中逻辑层，不因 Wiki 行为重排文档。此处是有意的编辑语义差异，不把自动模式称为完整游戏交互模拟。

**含水证据仅完成 API 静态水源保留分类。** [现有探测](../tools/dump_waterloggable_blocks.py) 覆盖 15,839/15,839 原版状态，使用 `water:0` 水源、`SetBlockNew(..., isLegacy=True, updateNeighbors=False)`、必要的配对夹具，并通过 `SetBlockStates` 保持预期语义状态；读回前景、状态与液体，形成 609 个阳性名称，当前没有部分阳性名称。证据见 [原生含水表](../tools/data/native_water_overlays_nemc_3.9.0.401155.json)。这证明所测 API 操作可保留水源和指定快照，不证明玩家正常放置的资格、两种顺序、流水、邻居 tick 后存活或自动熄灭。`WATERLOGGABLE_COMPLETE` 只能按这个谓词解释。

### F03：方块实体 NBT

**当前实现与边界：** 实际服务端测绘器使用事件登记区域，客户端只能申请读取该区域和清除登记；服务端 `GetBlockEntityData` 获取完整 NBT，客户端 palette 获取可见渲染字段，版本化 envelope 分开保存两者。捕获与传输期间锁选区，点击和清除静默拒绝，最后确认包解锁。未认可前客户端不显示确认特效或新金框。完整库存捕获已实测；进度检查仍只比较两层方块，不额外读取库存。

**当前外观与剩余验收：** 普通／铜双箱静态适配及已登记保留半格对照通过，顶底／其余材料方向仍待补齐。潜影盒六向、闭合纹理及半透明对照第四轮已通过；骷髅、凋灵骷髅、僵尸、苦力怕共 11 个明确姿态有原生／编辑器／投影证据，其余姿态及玩家、龙、猪灵头未全部验收。头颅 Float `Rotation` 与展示框 Float `ItemRotation` 已有原生观测和空间变换测试，展示框／旗帜附件仍未接入。陶罐四方向及 X/Z 镜像的原生投影已通过；编辑器独立参考、湿本体／水面及占用消隐仍待完成。告示牌本体材质与双面文字已接入，立式正背局部对照通过，悬挂、missing bank 和 occupied 矩阵尚未完整通过。床的成组 NBT 捕获／往返已补修，颜色外观仍待有效世界正控；结构方块及其他非默认内容外观继续按支持范围验收。未知字段无损保存。59 类型参考和字段覆盖见 [block-entity-data.md](block-entity-data.md)。

写回须定义可恢复字段、可写类型及必要的服务器限制；移除方块或改成别的材质时清除旧负载。扩展编解码时保留类型、大小和层级限制，不能把所有 NBT 值转成无类型普通数字或不加限制地接收。

**验收：** 同材质但不同内容的两个容器保持独立；箱子／潜影盒库存、告示牌文字等在完整往返中一致；副本编辑不修改原本的负载；NBT 单独变化也更新历史、脏块及模型缓存。支持范围需逐类说明，不能只用一种箱子证明全部方块实体可用。

### F04：多格方块与关联状态

**当前实现：** [block_groups.py](../behavior_pack/modern_projection/projection/block_groups.py) 识别门、床、双植物和双箱的关联部分；选择闭合、绘制／擦除、复制、替换、移动及变换会处理整组，并检测配对不一致。苍白苔藓地毯的 `upper_block_bit` 不会被误判成上下半多格结构。

**未完成验收：** 编辑器实机已覆盖小／大文档、跨 16³ 边界、门／床／高植物成组放置擦除和撤回重做；正式 WorldAdapter 的 32 个床状态／写入顺序用例通过。继续完成双箱及连缀方块的独立编辑器、完整投影和缺失投影画面检查，不能以配对数据完整代替外观正确。

**验收：** 门、床、高草跨选区、分块和图层时不意外留下孤立部分；不能配对时给出具体原因。世界写入顺序与最终结果由专用验收工具读回核对，生产写入仍遵守 F11，不增加逐格检查或回滚。邻接状态及静态外观纳入本项，原生不支持模型的适配关联 F05，实际世界回归关联 V03，缺失投影关联 F10。

#### 共用实施与验收要求

1. 按能力区分固定伙伴、可变链、邻接几何、邻接持久状态、同格多面和支撑依赖。名称表只用于当前版本的覆盖审计；实现优先复用状态模式和原生能力，个别语义以版本化适配记录处理。不得把新清单变成新的旋转名称白名单。
2. 固定伙伴保持已有成组事务；可变链、分支、脚手架／绊线等先用实际交互确定更新范围，明确链中截断和支撑移除结果。更新持久状态与重建外观是不同操作；导入和纯复制必须保留显式快照，不随无关编辑重算全部状态。
3. 每个家族覆盖放置、替换、破坏、自动／严格前景／严格背景、锁定层、文档／选区边界、复制、移动、旋转、镜像、撤销重做以及存档／旧格式／分享往返。多面附着和单格累积先核实原生增放／破坏语义；如需新增面／数量编辑入口，明确记录产品选择，不把待核实项冒充已确认的缺陷。
4. 编辑器渲染、完整世界投影和仅缺失世界投影分别验收。仅缺失投影覆盖初始已有格、动态放置／拆除、保留主／副半格、恢复，以及相邻真实与虚拟格混合；被隐藏格仍提供逻辑邻居，但不得继续输出可见像素。
5. 更新需跨 16³ chunk，必要时跨多个 chunk 传播。现有 3³ 局部上下文仅有部分家族证据，不能推定覆盖长绊线、脚手架支撑、整段植物或实体字段引用。先确定所需状态可否预计算，再决定原生上下文半径，避免无限扩张模型。
6. 普通玩家可打开的测试分页增加对应内置蓝图，保留稳定 family/case key、位置、原生预期状态和渲染参数；新增矩阵不能只在原版全览里摆一个默认单格。编辑器视觉测试引用这些蓝图，实际投影另建原生世界参考、固定相机、空背景及阳性控制；比较形状、纹理、位移和消隐残留。
7. 升级时对新 dump 做名称／状态键 diff，新增相关家族或属性必须显示为待审核，并更新清单 schema、来源指纹和能力／视觉证据。保存未知数据与“已验证正确”分别记录；不能让未分类新增块静默获得完成状态。

### F13：透明投影与后期星点合成

**依据：** 主线 [星点动态参数记录](PARTICLE_TRANSPORT.md) 明确保留“透明投影遮挡后期星点”。当前投影在原生星点之前写入深度，使透明建筑后方的星点被当作处于实墙后方。直接关闭深度写入又会让后绘制的天空覆盖投影；早期发光与后期 alpha 补偿实验在网易 3.9.0.401155 OpenGL 上触发 `Unknown blend target: 7`（`DestAlpha`），已经撤回。

`uncomplete` 的 [合成实验 `ecd9da1`](https://github.com/Happy2018new/better-building-editor/blob/ecd9da1a4dad99a24eb825d40e080a1b8da92c7a/docs/PROJECTION_COMPOSITING.md) 也未通过：远深度保护层挡住天空，却让后绘制的远岛和水面覆盖前方石英投影。GPU 工具的 52 项断言仅验证给定绘制顺序，最终游戏场景已否决该方案；不能将它算成主线已修复，也不能直接合并其两个实体方案。

待完成：在目标后端找到可保留投影颜色、透明透视星点和真实墙体遮挡的合成路径，同时保留连续透明度、草叶镂空、UI 显示及占用过滤。现有资料没有确认 BlockGeometry 的队列／离屏目标控制接口，不能先假定可用。

**验收：** 普通世界开启美丽的天空，天空／远岛／水面均不覆盖前方投影；“相机→投影→星点→墙”可见星点，“相机→投影→墙→星点”由墙遮挡。分别检查投影表面和星点，不能以投影消失或粒子穿墙换取通过。材质修改后冷启动验收。

待完成：先确认目标客户端支持的正式加载方式，再贯通顶点布局、矩阵／骨骼、时间与额外参数、PBR 输出及深度／混合状态；逐项验证编辑器模型、世界投影、群系染色、范围框与法杖／测绘特效。是否继续这一开发分支应单独决定，不能只把它归为 V01 的“再测手机”。

**验收：** 用普通可分发附加包冷启动，无需修改游戏安装资源；实际切换目标渲染后端并确认生效。核对材质绑定、动态参数、镂空与透明度、真实遮挡和画面一致性，再谈合入主线。2026-09-27 的离线矩阵不是当前主线所有新着色器的覆盖证明。

### F15：未引用分页回收

**依据：** [分享开发记录](SHARING_ASSESSMENT.md) 已承认取消后可能留下未引用分页。[archive.save_steps](../behavior_pack/modern_projection/projection/archive.py#L26) 先写页再返回索引；[Sharing.accept](../behavior_pack/modern_projection/projection/sharing.py#L214) 最后提交库索引，`close()`／`fail()` 只关闭作业或释放 I/O，没有清理已写页。[ClientBridge.clear_archive](../behavior_pack/modern_projection/projection/bridge.py#L231) 用于已知页数的删除清空，失败存档没有相应的页数清单。

第二轮用现有测试的内存存储替身复现：索引提交失败时库仍为空、I/O 已释放，但留下 1 页；在写完 2 页后关闭保存生成器，页仍存在；同一编号改存 1 页的小建筑后，第 2 页仍未被引用。取消用例验证的是底层生成器关闭路径，没有把它称为真实 UI 或系统磁盘复测。旧索引和草稿受保护的行为已经实现；问题是存储清理不完整。

待完成：记录未提交页及事务状态，在取消、写页失败、索引提交失败、后续较小保存和重启时安全回收；不得让迟到清理删除新事务复用编号的有效页。区分可清空内容与 SDK 无删除配置接口所留下的小空文件。

**验收：** 注入各写页／索引失败点，取消并重试更小或更大的建筑，检查有效索引和内容完整、无未引用大页积累；清理重试和跨重启行为可解释。普通大建筑保存与世界选区导入复用同一底层写页器，也应覆盖。
