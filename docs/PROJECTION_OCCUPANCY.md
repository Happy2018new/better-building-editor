# 客户端占位检测与批量投影更新

更新日期：2026-09-28。按用户要求移除九格逐格遮罩，以性能和连续显示为优先，保留一个完整世界投影实体。

## 当前方案与容量

- 已删除逐格索引 uniform、片元所属格计算、面导数以及逐格 discard。没有九格差量容量限制。
- Python 以目标索引集合合并变化；重复放置、破坏只保留最终状态。容量随投影目标数增长，当前文档上限 64×128×64，即 524,288 个目标格。256 是快速交互提示队列的上限，不是可记录变化数；未收到提示的位置仍由客户端巡检覆盖。
- 一个实体常驻两份完整几何资源。着色器仅选择当前整份缓冲并应用透明度；更新写入非活动资源，旧缓冲继续显示，准备后切换。自动更新不卸载、重新挂载几何，不拆分为多个投影实体。
- 每批有净变化才合并原生完整模型，不再按“超过九格”触发。连续施工持续提交，中间新增和反向变化会进入下一批；准备过程中完全撤回的变化可以取消提交。无变化不重建。
- 自动更新使用两个固定模型名，手动替换时交替两组名称，最多四个动态名称；不进入内容指纹缓存。全隐藏后保留追踪和已有实体；初始全隐藏时暂不创建实体，首次恢复可见目标再创建。

实现分为 occupancy.py（状态、差量、调度）、occupancy_scan.py（批量检测）、occupancy_initial.py（初始化快路径）与 occupancy_shader.py（整份缓冲选择）。vertex/fragment 不再接收逐格遮罩。

## 检测来源和未知状态

projection_missing 默认开启。同格出现任何非空气方块，包括错误材质、玻璃、半砖，均隐藏整格投影；恢复空气后显示。材质是否正确仍由独立建造进度检查判断。

只读客户端世界，不增加产品服务端占用通知。既有点击、触摸、挖掘事件提供快速提示，查询目标及六个邻格，重试 0.8 秒等待世界状态同步。其他玩家、命令或其他来源的变化，在客户端同步且区域已加载后由巡检发现。远处变化不保证即时响应。

实机发现：GetBlockPaletteBetweenPos 和 GetBlock 对未加载区块都可能返回空气，不能凭“返回了空气”断言区域已加载。现在系统初始化时监听 ChunkLoadedClientEvent / ChunkAcquireDiscardedClientEvent，以维度和 X/Z 区块坐标维护加载集合；查询前检查该集合。最终冷启动接收了 545 条在场区块记录，玩家所在区块有效。未加载、unknown 或无有效查询结果时保留最后已知状态，首次未知保持可见。切换维度停止旧投影并清理旧维度记录。

大投影按目标所在的 16³ 区域调用客户端 GetBlockPaletteBetweenPos(lo, hi, False)，保留空气与固定尺寸；校验调色板尺寸，比较缓存，未改变的区域跳过目标展开。只把结果应用到实际目标格。调色板缺项回退逐格查询，不把缺项当作空气，避免门上半部、床等省略项误判；缺项路径已有单元测试，特殊方块尚未穷尽实机验证。

## 性能改动与调度

1. 缓存客户端组件、目标集合、占用状态和按 16³ 分块的可见材质索引。每格的列表槽位用紧凑整数缓冲记录，移除采用末项交换，避免整张列表搜索。
2. 更新准备只对脏索引读取文档和修改缓存，再拼接缓存索引列表。原生仍接收完整调色板，但不再为每次改一格重新在 Python 中逐格遍历整个建筑并查询 BlockStore。
3. 初始化对均匀文档块和均匀世界状态使用连续行切片；混合块一次展开紧凑数据，按行构造目标位图，避免每个方块反复复制大整数或跨边界获取对象。
4. 精确巡检每 100 ms 最多 128 个工作单位，软预算 0.75 ms，并保留远处游标份额。大投影批读间隔至少 50 ms，结果消费每次最多 256 项、软预算 0.75 ms。少于 1,024 个目标时关闭持续批读，避免仅有少量方块却扫描巨大边界。
5. Python 更新准备软预算 1.5 ms；提交后的冷却至少 350 ms，随原生调用耗时增加。预算只能在可让出的工作单元间生效，不能中断同步 SDK 调用或保证整帧耗时。

双缓冲仍增加原生模型内存及非活动缓冲的顶点处理开销。未测量移动端 GPU 和内存收益，不能把 Python 调用减少等同于 FPS 提升。

## 大建筑闪动修正

实机证明原生 Combine 返回模型名不等于渲染线程已完成网格生成。满体积模型的同步调用仅约 7 ms，但后续网格生成仍可能超过 0.5 秒。旧固定 150 ms 切换方案在 249 张采样图中出现 37 张整片消失，不能因为实体 ID 保持不变就判定无闪动。

当前在旧缓冲持续显示期间等待：

    max(0.15 秒, 文档体积 / 419430.4 秒, 本次同步调用耗时毫秒 × 0.04 秒)

64×128×64 的体积项为 1.25 秒。该等待与冷却期间继续采集变化；它是根据实机观察设置的保守等待，不是 GPU 完成栅栏，也不是所有硬件上的无闪动保证。缓冲 uniform 写入失败时保留已提交的模型及占用快照，避免状态提前提交。

最终冷启动测试中，524,288 格实心投影连续 128 次世界变更，采样 224 张画面、发生 5 次批量重建，未施工区域检测像素在全部采样中保持显示。小模型连续 64 / 72 次变更分别采样 119 / 120 张，重建 13 / 14 次，两组同样全部保持检测区域显示。已人工查看实机完整截图与采样拼图。截图间隔约 50–70 ms，不代表检查了每个 GPU 帧。

## 玩家地面、高处离体相机的可见性

旧路径把实体锚点跟随离体相机移动到高处，开启和关闭缺失过滤都可能不可见。单独提高实体绘制距离不足以解决。

当前将方块模型实体锚定在玩家脚部上方一格，通过几何 offset 补偿到投影的真实世界位置，使实体留在玩家所在的加载区域；离体相机移动不重建模型。范围框和测绘效果沿用自己的相机跟随。大小投影均管理本地实体绘制距离，关闭时按原有所有权规则恢复。

最终回归让玩家保持原地，分别测试原高度、抬高 20 格、抬高 127 格，缺失过滤开启/关闭共六组全部通过真实像素检查。+127 格天空背景对比低，使用显示与隐藏实体的差分而非仅靠目视或元数据判断。此检查证明对应场景可见，不代表穷尽所有非完整模型的面结构、角度和透明排序。

## 64×128×64 实测

环境：网易 Windows 开发客户端 3.9.0.401155，本机 RTX 4060 Laptop GPU；独立冷启动平坦世界、单投影实体。表中为一次最终回归观测，不是平均值或最坏情况承诺。

| 样本 | 实际目标格 | 初始化优化前观测 | 最终初始准备至逻辑提交 | 64 格批量放置至状态收敛 | 无交互提示的远端单格变化至提交 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 完全实心 | 524,288 | 115.8 s | 11.20 s | 3.49 s / 2 次重建 | 4.26 s |
| 外墙与楼板建筑 | 66,852 | 41.2 s | 12.17 s | 3.56 s / 2 次重建 | 4.15 s |

初始计时包含测试草稿构造、分帧调度和宿主查询，完成点是逻辑提交，不是 GPU 栅栏。更新计时包含世界同步、检测、批量准备、缓冲等待和宿主查询。未提示的远端变化只有客户端巡检，位置在建筑远端顶角。全部案例随后恢复方块并核对目标数量、同一实体和最终状态。

本次实心模型几何函数同步调用约 6.97–7.82 ms，其中原生 Combine 约 6.90–7.74 ms；建筑样本约 2.75–3.58 ms，其中 Combine 约 2.68–3.50 ms。这些数字不包含之后的原生网格生成或 GPU 时间。prepare_ms 记录跨帧准备的墙钟时间，不是某一帧的阻塞时间。

另保留 20,480 格场景的 5 秒 client/wall profiler 基线/候选报告；其回调统计不能用来推算 FPS。大建筑更新采用有意延迟的批量收敛，不承诺每次放置都立即消隐。
