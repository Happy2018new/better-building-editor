# R29 床边界与写入生命周期组合检查

来源为 `af9c628c` 的实际上传、WorldJob.validate_write、WorldAdapter 和 server.tick 链，SDK 接口替换为记录器及可控失败。共 **280 组**：7 种变换 × includeAir 两种取值 × 5 种床／分层模式 × 4 种生命周期变化。

五种输入包括不完整床、正常床、含水、背景晋升和水前景晋升；生命周期变化包括切换维度、无离开事件的离线、在线查询 UTF-8 字节异常和维度查询 UTF-8 字节异常。批次只将真实 step 的 budget 固定为 1，未替换床验证或写入逻辑。

全部检查均停止后续 setter，保留成功／失败前缀及首处失败，不重复终结；原请求权限检查恰好一次。每组随后真正发起新请求，新适配器、床配对缓存和当前维度正确，能继续写入。五项源码输入在执行前后 SHA 相同。

[index.json](index.json) 保存 4 份去重原件，包括驱动、详细报告、原 README 和原始索引，约 9KB。没有改动产品或永久 tests，没有启动 MC。SDK mock 不模拟引擎自动生成床的另一半；一个逻辑格完成后取消可能保留部分 NBT／液层，沿用既定不回滚语义，不能由本结果宣称原生床物理验收通过。
