# Settled Single Pool Runtime Plan

This is a separate S/SE diagnostic after the frozen distance-cache A/B. It
does not edit its host, project, plan, receipts or results. There is no launch
entry. Use its exact existing session and owner, retained exit observer and
main DisabledSkin watcher. Root must schedule both runtime and WGC explicitly.

```powershell
$env:OPENBLAS_NUM_THREADS='1'
python -B .runtime/water-ui-submit-r21-v1/runtime.py run --scheduled-by-root --session <CACHE_SESSION_FILE>
```

The A/B must report completed, restored and source_unchanged. The new report
and PNGs go only to `.runtime/water-ui-submit-r21-v1/result/`. The entry opens
one ordinary frozen pool after A/B restores its workspace. Its eight published
water dolls must have settled before any candidate call. No other fixture,
world renderer, shared Scene class or cold instance is used.

The exact sequence is S baseline -> SE -> S restore -> SE repeat -> final S.
Each phase uses the same original models, poses, depth -50 and payloads, waits
for two natural asynchronous ID observations after the same 0.6-second settle,
then reads all four actual native uniforms. Every phase has its own wet and
hidden-water PNG. All allocated bank/group IDs must be independent and each
published ID must remain equal to its initial ID. Geometry and session depth
must match the initial snapshot exactly. Any API failure, ID alias/change,
incorrect tag134/uniform readback or geometry/depth change rejects the run.

SE repeat additionally exercises one ordinary `move_depth(1)` and return on
the same pool. Only those eight owner instances temporarily receive the SE
method while the ordinary controls update. The step gets one native PNG;
the returned logical/native state must equal the original state. This can
falsify preservation but cannot qualify all shared depth/occlusion behavior.

Capacity, exact observer identity, watcher heartbeat and native assertions
are checked before and after each phase and each capture. Runtime boundaries
require at least 6 GiB available commit, at most two effective games and fewer
than 210000 owned handles. The source/resource closure is checked against the
frozen cache project. OPENBLAS_NUM_THREADS=1 is process-local.

The automatic report never accepts a repair. Actual native PNG review must
reject any cow pixels, wrong water silhouette, changed depth or occlusion,
failed wet/hidden control, nonreversible skeleton restore, or failed cleanup.
If the S baseline is already visible, the result is inconclusive for repairing
the invisible state, even when SE also looks correct. The initial construction
ordering and production default remain unqualified and disabled.

Finally cleanup restores each owner method, ordinary depth, original S calls,
all four uniforms, closed flag, workspace and saved profile. Cleanup does not
depend on passing the 6 GiB gate. No stop/activation/input/window mutation is
issued. If the host is interrupted, do not replay run. Inspect the saved report
and recover the same exact existing session:

```powershell
python -B .runtime/water-ui-submit-r21-v1/runtime.py recover --scheduled-by-root --session <CACHE_SESSION_FILE>
```

A transport failure preserves the in-game `_water_ui_se` object for recovery.
Root retains the session/observer and decides when normal game shutdown is due.

Offline preparation checks:

```powershell
python -B .runtime/water-ui-submit-r21-v1/check_runtime.py
```

After a completed/restored run and actual PNG inspection, independent fixed-ROI
pixel counts can be generated without another game connection or capture:

```powershell
python -B .runtime/water-ui-submit-r21-v1/analyze_runtime.py
```

This writes a separate analysis.json, preserves all raw captures and never
accepts a repair. Any baseline wet-minus-hidden signal marks the invisible-state
repair inconclusive. Its historical fixed ROI requires the exact original
1994x1105 native viewport; a changed viewport rejects this metric instead of
rescaling images. Pixel counts alone do not identify cow geometry or prove depth.
