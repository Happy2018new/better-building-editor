# 性能检查与优化（阶段 67）

2026-09-23，在 Windows 网易开发客户端 3.9.0.401155、1920×1099 客户区实测。原实例 scene-polish66，候选实例 perf67；基线退出后才对候选实例计时，没有同时运行两个测试游戏。默认草稿为 24×16×24、1,307 个方块。

## 界面更新

通过 `_pyreact_flush` 的游戏线程计时，分别检查首次和重复操作；cProfile 仅用于查调用热点，不把带 profiler 的数字用于前后提速比较。全屏刷新、重复排版及不必要的控件销毁是主要问题。此次修改：

- 静态文字 Element 使用最多 512 项的 LRU 缓存；颜色、字号、宽度、缩放都进入缓存键。动态文字不共享可修改的 props。
- 动态标题/方块名称的字形池只更新改变的字形；空闲字槽不再每次重复隐藏，字体和实际排版保持原样。
- 材质通道的按钮保留，切换需要不同通道的工具时隐藏/恢复，避免移除控件隐式触发原生整屏刷新。
- Primitive 的 `apply_props` 可以显式返回 False，免除仅由 props 造成的整屏刷新；默认 None 保留原行为。只换 Button 回调时更新宿主回调表，仍使用最新 handler。挂载、显隐和布局继续正常提交。
- 固定宽高的叶子使用声明尺寸；自适应文本继续量测。

下表为相同操作的最大单次 UI 提交耗时，单位毫秒；不是整帧耗时或 FPS。单轮极值会受调度波动影响。

| 操作 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 目录连续两次下一页 | 44.41 / 41.36 | 37.32 / 33.08 |
| 目录上一页 | 40.63 | 32.22 |
| 目录切木材 / 彩色方块 | 43.14 / 43.84 | 35.16 / 37.58 |
| 目录第一次打开 | 77.05 | 60.28 |
| 目录重复打开 | 19.18 | 17.79 |
| 重复进入建筑库 | 18.62 | 15.92 |
| 从投影返回工作台 | 26.18 | 22.49 |
| 选取模式 / 换材质模式 | 37.82 / 21.36 | 27.67 / 15.76 |

并非所有操作都等比例改善：参数页重复切换约 13.6 ms，基本不变；首次展开尚未创建的工具控件仍可能约 60–100 ms。因此保留分批预热，不能宣称已消除全部首次操作停顿。优化没有关闭果冻、选项滑动或进出场动画。

## 验证

- 第一阶段全套 257 项离线测试通过，新增检查最新回调生效、纯属性快路径不丢显隐/布局，以及固定尺寸和自适应文本的区别。
- PC 与 F11 原生触屏：选取、放置、擦除、浏览按钮，材质通道反复增减及副材质真实点击通过。原生命中控件保留，回调仍是当前通道。
- PC 与 F11 场景子页切换、焦点视图、底部间距检查通过；已读取截图检查文字、按钮和模型显示。
- 复现脚本：`tools/profile_editor_switches.py`、`profile_pane_switches.py`、`profile_catalogue.py`、`profile_ui_invalidation.py`、`verify_performance_ui.py`。使用 `tools/run_live_check.py --session ... --owner ...` 路由至独立实例。

性能工具的 native.cpu 能力检查显示缺少可选 DLL，未使用或推断 C++/GPU 性能采样结果。F11 是 Windows 开发客户端的原生触屏模拟，不能替代 Android/iOS 真机多指验证。
