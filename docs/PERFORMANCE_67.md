# 性能检查与优化（阶段 67）

2026-09-23，在 Windows 网易开发客户端 3.9.0.401155、1920×1099 客户区实测。原实例 scene-polish66，候选实例 perf67；基线退出后才对候选实例计时，没有同时运行两个测试游戏。默认草稿为 24×16×24、1,307 个方块。

## 界面更新

通过 `_pyreact_flush` 的游戏线程计时，分别检查首次和重复操作；cProfile 仅用于查调用热点，不把带 profiler 的数字用于前后提速比较。全屏刷新、重复排版及不必要的控件销毁是主要问题。此次修改：

- 静态文字 Element 使用最多 512 项的 LRU 缓存；颜色、字号、宽度、缩放都进入缓存键。动态文字不共享可修改的 props。
- 动态标题/方块名称的字形池只更新改变的字形；空闲字槽不再每次重复隐藏，字体和实际排版保持原样。
- 材质通道的按钮保留，切换需要不同通道的工具时隐藏/恢复，避免移除控件隐式触发原生整屏刷新。
- Primitive 的 `apply_props` 可以显式返回 False，免除仅由 props 造成的整屏刷新；默认 None 保留原行为。只换 Button 回调时更新宿主回调表，仍使用最新 handler。挂载、显隐和布局继续正常提交。
- 固定宽高的叶子使用声明尺寸；自适应文本继续量测。

下表为相同操作的最大单次 UI 提交耗时，单位毫秒；不是整帧耗时或 FPS。单轮极值会受调度波动影响。

| 操作 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 目录连续两次下一页 | 44.41 / 41.36 | 37.32 / 33.08 |
| 目录上一页 | 40.63 | 32.22 |
| 目录切木材 / 彩色方块 | 43.14 / 43.84 | 35.16 / 37.58 |
| 目录第一次打开 | 77.05 | 60.28 |
| 目录重复打开 | 19.18 | 17.79 |
| 重复进入建筑库 | 18.62 | 15.92 |
| 从投影返回工作台 | 26.18 | 22.49 |
| 选取模式 / 换材质模式 | 37.82 / 21.36 | 27.67 / 15.76 |

并非所有操作都等比例改善：参数页重复切换约 13.6 ms，基本不变；首次展开尚未创建的工具控件仍可能约 60–100 ms。因此保留分批预热，不能宣称已消除全部首次操作停顿。优化没有关闭果冻、选项滑动或进出场动画。

## 验证

- 第一阶段全套 257 项离线测试通过，新增检查最新回调生效、纯属性快路径不丢显隐/布局，以及固定尺寸和自适应文本的区别。
- PC 与 F11 原生触屏：选取、放置、擦除、浏览按钮，材质通道反复增减及副材质真实点击通过。原生命中控件保留，回调仍是当前通道。
- PC 与 F11 场景子页切换、焦点视图、底部间距检查通过；已读取截图检查文字、按钮和模型显示。
- 复现脚本：`tools/profile_editor_switches.py`、`profile_pane_switches.py`、`profile_catalogue.py`、`profile_ui_invalidation.py`、`verify_performance_ui.py`。使用 `tools/run_live_check.py --session ... --owner ...` 路由至独立实例。

性能工具的 native.cpu 能力检查显示缺少可选 DLL，未使用或推断 C++/GPU 性能采样结果。F11 是 Windows 开发客户端的原生触屏模拟，不能替代 Android/iOS 真机多指验证。

## 分块批量编辑

此前，即使选区已是紧凑位图，部分选区、带蒙版填充和薄壳仍对每格反复进行坐标、选区、材质及统计查找。现在按 16³ 分块的选择位图写入，先排除锁定层，再应用材质条件；均匀分块的完整 Y 平面通过数组切片写入。混合分块继续逐项判断，统计按分块汇总。使用原有写时复制和原子发布，取消不修改草稿，撤销/重做继续保留。

同一 perf67 实例内，通过 `profile_edit_jobs.py` 创建独立测试文档、按帧执行 EditJob；不加载到玩家草稿，也不操作世界或建筑库。下表是游戏 Python 2 的数据处理累计时间，排除模型构建及 UI；源码热装前后使用同一负载和计时方式。

| 64×128×64 数据操作 | 修改格数 | 修改前 CPU/ms | 修改后 CPU/ms |
| --- | ---: | ---: | ---: |
| 全区均匀填充 | 524,288 | 1.69 | 1.57 |
| 一格厚空心长方体 | 39,944 | 438.93 | 20.18 |
| 部分选区填充，已有方块蒙版及 3 个锁定层 | 472,812 | 5,003.21 | 137.31 |
| 部分选区擦除及 3 个锁定层 | 472,812 | 4,185.88 | 136.76 |

后三项约减少 95.4%、97.3%、96.7% 的数据处理耗时。修改后每次 `step` 峰值约 6.6–8.0 ms；单个分块不能在任意指令间抢占，因此是软时间预算。原有整块填充快速路径继续保留。数据撤销/重做均约 0.02 ms，不能将其解释为整栋模型已经显示完成。

新增与逐格实现对照的回归覆盖空气/已有方块/指定材质蒙版、跨分块的不规则选区、锁定层、填充/擦除/四种轴对齐形状、材料数量和逐层计数、旧快照不被修改以及撤销重做。越界选区在发布前拒绝。全部 259 项离线测试通过。

完整实机流程还覆盖最大薄壳、撤销/重做、连续 20 次单格修改及连续撤销；撤销和重做均复用原几何，没有新模型构建。大尺寸旋转验证使用两倍缩放并前移 32 格，PC/F11 各测两个小角度区间及 ±45° 大角度拖动，每个区间持续 6 秒，确认持续按住、角度确实改变且几何构建次数不增加。旋转调用间隔的 p95 约 PC 21.9–26.4 ms、F11 11.2–14.3 ms；这些是指定测试设备上的采样，不是跨设备帧率保证。

目录和工具搜索另通过 PC 与 F11 原生连续输入/删除各 56 次采样，聚焦灰底、光标字体整数缩放、中文筛选和弹窗隔离保持正常。原生 Assert 检查随每个 UI 调试请求执行，未发现断言窗口。


## 同步提交与第二次排版

最大薄壳预览的逐帧 cProfile 显示：每批创建 4 个分块控件时，原生 `SetLayer` 重复调用输入路由重建；同时，尚未打开的弹窗所用 `FadePrimitive` 是 Panel 子类，却因旧代码只按类名识别 Panel，被误当成需要原生刷新后量测尺寸的叶子。即使实际修改只发生在模型容器，仍多执行一次全树布局及整屏刷新。

- 挂载和单次同步提交内暂存相同的 `gui.handle_input_mode_change` 调用，最终控件树就绪后执行一次。原生属性写入、不同参数的通知、嵌套提交及异常清理均保留；缺少该辅助函数的引擎使用原路径。此范围不跨帧，也不覆盖玩家输入事件分发。
- 后测量识别 Panel/Label 的子类；对绝对定位且两侧锚点已确定的轴不再依赖原生量测。真正具有自适应原生尺寸的 Image 等仍保留后测量。
- 未改动准确方块几何、双缓冲、防闪提交、动画时长或手势规则。

同一 perf67 实例、相同 64×128×64 / 39,944 格薄壳、相同测试脚本，不带 profiler：

| 最大薄壳创建过程 | 本阶段前 | 本阶段后 |
| --- | ---: | ---: |
| 预览调度 `previewWall` | 4.342 s | 3.525 s |
| Python 渲染帧回调 p95 | 70.62 ms | 39.11 ms |
| Python 渲染帧回调最大值 | 138.98 ms | 113.60 ms |
| 渲染帧回调间隔 p95 | 80.73 ms | 47.81 ms |

`previewWall` 是游戏内部预览任务的调度计时，包含任务分帧及其间的 UI 开销，不是 GPU fence。回归另外等待所有分块的 pending 清空。宿主脚本的 `observed_wall_s` 包含 MCP 轮询和往返，因此没有拿它宣传精确提速。证据为 `.runtime/perf67_workflows_after.json` 与 `perf67_workflows_batched_final.json`；cProfile 只用于定位热点。

收益主要在批量控件挂载。普通页面已经复用原有控件，本阶段再测的目录翻页约 35–38 ms、木材/彩色分类约 35–36 ms，和第一阶段结果处于相近范围；不是所有操作都继续下降。撤销/重做和连续编辑仍可复用几何，但偶发的 Python 提交峰值仍存在，连续 20 次修改/撤销的测试中出现约 200–300 ms 峰值。尚未把这些峰值归因于未经验证的 GC 或 GPU 原因，也没有全局关闭 GC。首次创建最大建筑仍需数秒，不能宣称整体卡顿已经消失。

## 最终复测

- 全套 **264 项离线测试通过**。本阶段增加确定尺寸/自动尺寸/Panel 子类的后测量检查，以及输入路由合并、不同参数、嵌套、异常恢复和 effects 提交顺序回归。
- `verify_commit_performance_regressions.py --visual` 的 **147 项实机检查全部通过**：F11 小/大模型持续按住往返旋转、暂停后继续、松手结束、连续轻触放置/擦除/吸管/框选；4:3 与 16:9 布局；P 打开和关闭、删除/重命名/方块目录弹窗的中间位移与透明度、反向切换、减少动态效果；PC/F11 快速输入删除、中文筛选、焦点、整数原字体和弹窗输入隔离。测试保存并恢复草稿、模式及窗口大小。已读取工作台、确认框和方块目录动画采样图。
- `verify_performance_ui.py` 再次通过 PC/F11 实际模式点击和反复增减材质通道后的点击，确认最新 handler 生效、原生按钮被复用。
- `profile_editor_workflows.py --label navigation_final --navigation` 再测最大薄壳、撤销重做及连续编辑，并覆盖 1×→2×→8×→4×→1× 缩放、不同方向平移与 0→16→48→24→0 格视线深度。所有视角改变 **新增模型构建 0 次**，文档仍为 39,944 格；导航 Python 回调 p95 8.64 ms，回调间隔 p95 23.54 ms。此轮薄壳预览调度为 3.166 s，说明单轮计时有波动，保留前一轮 3.525 s 作为表内数值。
- 连续切换材质 48 次：无内容版本更新、无模型重建，Python 回调 p95 约 0.96 ms，与基线基本相同。此路径没有发现需要进一步改动的明显热点。
- 游戏内 **Python 2 编译 60 个框架和业务模块通过**，最新错误日志为空，独立原生 Assert 窗口检查为空。

上述实机结果来自 Windows 开发客户端；F11 模拟覆盖原生触控事件绑定与捕获，未据此声称已测 Android/iOS 硬件性能。
