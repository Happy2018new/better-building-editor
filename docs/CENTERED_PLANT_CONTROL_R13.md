# Centered poppy original-texture control R13

The R12 h0 control had a visible native poppy (12,370 changed pixels) and an
absent projected poppy (zero). The new control keeps the centered-cross
candidate from `tools/data/centered-plant-candidate-r12-v1/`: native
`flower_rose.png`, unit height, zero X/Z translation and the existing fern
rotations/UV. Its production profile stays disabled. There is no fitted
translation or recovered native random-position claim.

`tools/isolated_centered_plant.py` validates all candidate bytes against their
pins and the unchanged generator output, then journals four exact changes in
the owned test project: behavior definition, block geometry, appearance and
atlas registration. Original files are backed up before any mutation. Each
replacement publishes a complete staged file. Cleanup restores exact original
bytes and original absence; it refuses and reports external edits. Native
poppy texture bytes are never overwritten.

The fresh plan records both the original BP/RP inventory and the predicted
installed inventory. The supervisor verifies the installed inventory before
the single launch. Current host adapters, candidate files, generators, source
manifest and runtime helper scripts are pinned. A repaired background startup
contract is a prerequisite, so the provisional plan is not a launch result.

The candidate capture order establishes native plant/blank and projected
plant/blank first. The unchanged 80-pixel positive-control gate must pass in
both modes before snow/covered captures begin. Every native capture stops the
virtual projection. Every projected capture clears only the real target,
waits for a blank client palette, and checks blank again after the image;
the separate stone support remains. This prevents an interleaved native
snow/covered fixture from contaminating later projection frames.

All original thresholds remain: fixed physical image 1994×1105 and crop,
threshold 20, same-session stone-cell ROI, three-pixel comparison tolerance,
precision/recall at least .75 and visible-area ratio .5–2. The fresh native
and projection frames retain first attempts, actual render-event waits,
GetForward alignment, actor/offset submissions and exact restoration. One
launch has total/work/cleanup/launcher limits 240/190/50/90 seconds. It uses
an owned private world, background WGC, no desktop input/activation/resize,
and a root-coordinated slot within the five-game limit.

This control concerns h0 full-world projection. Even a successful diagnostic
does not qualify the editor, missing-mode boundaries, other snow heights,
other positions, or the production profile. Those remain separate checks.

Offline checks for this preparation: 13 candidate/resource tests, 28 finite
h0-control tests and unchanged static-plant generator output passed. Manual
host-source review covered the installer, candidate schedule and restoration;
the MOD reviewer parsed the unchanged `plant_position` module with no finding.
An independent reviewer found and then verified the correction for native
fixture contamination before the plan could be run.
