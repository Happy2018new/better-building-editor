# 原生物品渲染接入边界与后续验收

状态：设计与基础适配完成，正式编辑器／投影接线尚未完成。R13 在一个受管游戏中确认了原生普通钻石剑及附魔光效在 PaperDoll 内可见；世界实验有可见结果但验收控制失败，不能将其写成投影已经支持。

## 职责划分

| 模块 | 唯一职责 | 接口边界 |
| --- | --- | --- |
| 现有 `entity_overlays` | 从已保存的 typed NBT 提取本地原生物品字典；拥有并增量同步一个 actor 上的绑定 | 不读取服务端库存、不生成 actor、不决定相机、不更改文档 NBT |
| 后续 `frame_item_render` | 持有一个渲染批次的 actor/model/binding 生命周期 | actor ID、世界骨骼 model ID、UI model ID、item binding ID 分开登记；删除绑定、卸载 UI 后才释放 actor |
| 后续 `frame_item_scene` | 接入已有 Scene 的相机、裁切、切面、可见单格与 tile 调度 | 消费渲染计划；不管理网络权限，不重建另一套相机 |
| 后续 `frame_item_projection` | 把投影原点、方向及 missing-only 结果转换到世界渲染计划 | 世界遮挡、已建单格消失和背景连缀上下文独立验收 |
| 后续 `frame_item_profile` | 版本化的物品单位、轴与材料能力数据 | 明确 UI 和 world 的不同单位；未知版本／未知姿态不宣称验收 |
| 后续服务端 `render_actor_owner` | 固定类型、固定上限的 actor 登记和释放 | 不传 item/NBT，不提供任意实体类型或已有实体操作接口 |

R13 给 `BoundItems` 添加显式 `model_family=('minecraft'|'skeleton')` 与 `is_client_entity=bool` 参数；默认仍是原来的 Minecraft 模型／客户端 actor。移除、姿态 setter 和重新绑定使用同一个显式标志，原生负值、布尔值、字符串或 `None` 身份不会进入清理账本。这个适配器尚未在 Scene／projection 中调用，不能算用户功能完成。

## Actor 批次与服务端边界

优先继续调查完全客户端的固定资源 actor 路径，避免为了渲染引入服务端 actor；现有实验证明的是一个具体客户端 anchor 的 `SetModel=-1`，并没有排除所有客户端资源定义。如果最终只能使用服务端 actor，则采取固定的小批次，而不是每方块创建一个服务端实体。

第一版建议一个页面 owner 使用一个 actor、至多 64 个物品绑定，投影 owner 另有一个 actor；每玩家至多两个 actor。这个上限是明确的预算，后续须按真实性能结果调整。普通页面／投影不申请 OP，也不调用玩家或库存接口。

客户端仅提交协议版本、owner 类别与生命周期 serial。服务端从已认证事件的玩家 ID 决定 ownership，固定实体类型、固定 NPC 参数、固定数量上限；返回只属于该玩家的新 actor ID。关闭页面、结束投影、断线、换维度、超时及服务器销毁都触发同一幂等释放链；过期异步回调只释放自己的新 actor，不发布到新页面。客户端不能提交任意实体类型、已有实体 ID 或服务器物品／NBT 请求。

编辑器 owner 的 actor 出生点由服务端根据玩家位置选取已加载位置；物品相对位置、UI 比例与旋转仅由客户端渲染计划决定。投影需要世界原点，但不应向 actor owner RPC 偷塞任意坐标：应复用服务端已登记的投影 owner／原点，或先确认可用的客户端纯渲染位移接口。这个世界锚定选择仍待实现和验证。

临时 actor 是否被其他玩家看见也必须独立验证。NPC 标志不等于仅所有者可见；未经验证，不可宣传该服务端路线能保持原投影的客户端私有显示。

## 各层身份与失败处理

同一 render owner 保存 exact actor ID。世界骨骼 `SetModel` 得到的 model ID 与 PaperDoll 的 deferred model ID 只用于各自原生接口；`BindItemToSkeletonModel` 的第一个参数始终是 actor ID。item binding ID 可以在旧绑定被正确移除后被引擎复用，不能以整数“曾出现过”认定冲突；判断须包含 actor ownership、绑定生命周期与当前账本。

绑定或 setter 失败时保留当前可重试条目；内容发生变化时先成功移除旧绑定，再创建新绑定；删除失败不能清空 owner，防止孤儿物品。关闭链先移除绑定、卸载 UI，再请求服务端释放 exact actor，最后分别观察服务端和客户端不存在。每个批次有生命周期 serial，异步回调不得接入已关闭的批次。

## 大版本维护合同

保存 profile schema、协议 schema、网易运行时版本、国际版状态表来源、资源 hash、轴映射、UI/world 单位和能力矩阵。此次 UI `1/16` 在固定骨骼／钻石剑上完整可见；world SDK 默认 `1` 可见，UI 值直接用于 world 会得到微小物品。这些是该版本路线的证据，不能合并为一个“通用 scale”。

升级时先 diff 仓库内 dump；以公开内置蓝图更新多种物品和 actor 数据，再运行自动普通负控／附魔正控、六面八向、cutaway、missing-only、遮挡和清理回归。只有 profile 的运行时与资源 hash 一致才允许沿用其校准。未知物品数据保持文档原值，并报告渲染未支持，不能丢弃 NBT。

## 尚未完成的验收

- 正式 Scene 接线与页面生命周期，界面切换／版本更新／错误时的无残留清理。
- 六个面对、八个 ItemRotation，物品展示架各槽位、旗帜／地图／方块物品／复杂 userData。
- 原版实体内容作为独立外形、位置、比例 oracle；目前钻石剑可见不能覆盖全部物品。
- 编辑器共用深度、方块遮挡、切面、含水前后可见性，与原有 tile 相机对齐。
- 世界背景静止的投影验收，已建单格隐藏后同批物品消失且邻居上下文保留。
- 服务端 actor 的跨玩家可见性、固定数量预算、disconnect／dimension／超时释放。

R13 世界 V1 在隐藏 UI 后被错误布局守卫拦截；V2 的 UI 比例产生微小物品且背景 torch／粒子导致负控不稳定；V3 的默认比例能看到完整世界物品及随时间变化的附魔色彩，但本体 72 像素低于预先冻结的 80 门槛，恢复差异 1,124（移动动物／背景），所以正式结果保持失败。失败原件应和正向 UI 原件一起保留；不能以事后改 ROI 或降低阈值覆盖旧结果。
