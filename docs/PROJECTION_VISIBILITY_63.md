# 世界投影可见性、线宽与阴影修复

2026-09-23，基于 `0463966`。

## 原因与实现

- 网易 3.9 的客户端实体可见性判断没有完整覆盖挂载的巨大方块几何和着色器扩展后的外框。建筑中心仍在世界中，不代表对应实体一定会提交绘制；靠近角点低头、进入椭球底部时可以稳定复现整栋投影或整个外框消失。
- 调整 `visible_bounds`、增加不可见大立方体、扩大实体碰撞盒的实验没有可靠修复实际画面，均未保留。移动动物会污染前后截图差分，因此不能把小量差异当作范围框恢复。
- 正式方案在 `GameRenderTickEvent` 中把两个客户端实体的绘制锚点保持在相机前方 4 格。方块模型使用 SDK 的偏移接口补偿，外框在完成原生骨骼变换后，通过 `WORLD`、世界坐标差和 `VIEWPROJ` 补偿。建筑原点、范围尺寸、方块数据不移动；无需重新生成调色板或模型。已提交模型独立记录，准备下一份投影期间仍可正确更新旧投影；原生临时失败下一帧重试。
- 位置/实体不变时不提交变换；关闭投影、切维度、销毁时清空跟踪状态。小建筑和大建筑走同一锚点补偿。仍仅创建客户端实体，不增加服务器实体、网络广播或服务器方块修改。
- 世界外框线宽固定为 0.045 格。旧公式按最长边增长，128 格高时达到 0.48 格；现不随建筑尺寸增粗。近距离透视仍会自然使线条占更多屏幕像素，远距离仍会更细。色彩场与交点渐变保持原逻辑。
- 建筑实体和外框实体均调用 `CreateModel(entity).SetEntityShadowShow(False)`。此接口返回 `None`，不参与挂载成功的布尔判断。移除的是实体脚下的圆形黑影，正常世界深度遮挡保留。

## 验证

- 246 项离线测试通过；新增相机位置变化时世界坐标不变、静止不重复提交、准备新投影仍跟踪旧投影、外框重新开启及原生临时失败重试。修改的 4 个 Python 文件通过游戏内 Python 2 编译。
- 独立实例 `763e2492b5a1459cb97e354d211fb8dd` 加载新着色器。`verify_projection_visibility.py` 使用 64×128×64、20,649 方块空心椭球，实际查看低处正视/侧视、角点平视/低头、内部底面/侧面和远处总览截图。低头角点有连续外框，内部底面与侧面持续可见。
- 同一远景镜头分别使用中心锚点参考和相机锚点，中央对照区域内超过 35 色阶的差异像素为 0，确认几何未发生平移。连续 24 次、每次 15° 的完整转向中，方块模型及两实体 ID 不变。
- 用 Windows 嵌入式 Python 2 的 `time.clock` 采样 516 帧，锚点更新函数 P95 为 0.1034 ms、最大 0.3237 ms。仅代表该函数的墙钟耗时，不是整场景、GPU 或手机帧率。初次使用 `time.time` 的粗粒度采样不用于性能结论。
- `verify_projection_shadows.py` 在独立世界预先确认为空气的 196 格位置临时铺设石头平台，实际截图对比同一个近地外框启用/禁用原生阴影；可清楚看到角点黑斑出现与消失。最终脚本断言显著像素变化，随后读回确认平台全部恢复为空气。此前落入地形或未正确铺设平台的探索截图不算验证通过。
- 所有测试恢复测试玩家位置/飞行、相机、草稿及投影选项，没有修改用户建筑库、偏好或剪贴板。原生 Assert 窗口检查为空。引擎日志仍有共享日志轮转的 `WindowsError 32`，未把它描述为“错误日志全空”。未做 Android/iOS 硬件实测。

## 重复执行

通过 `tools/run_live_check.py --session <独立实例 session.json> --owner <owner>` 执行 `verify_projection_visibility.py <标签>` 或 `verify_projection_shadows.py`。着色器变更需新进程加载；本轮 `ReloadAllShaders` 曾导致 IPC 超时，不把热重载调用成功当作着色器已生效。阴影脚本会临时修改测试世界，不用于用户建筑所在地。
